## 背景（なぜ変えるか）
現行は「Spreadsheet＝主戦場、Project OS＝戦況レーダー」思想。実運用で以下が判明：
(1) 更新の駆動源が期日切れアラートで、更新が目的化した
(2) 13列の表とメタ6項目が思考でなく事務を要求した
(3) シート共有の必要があるPJは1つだけ・見せるだけだった
(4) 承継・IPO体制・仲間探し等のPJは数週間イベントが無く思考だけが動くタイプで、
    イベント駆動の表形式と合わない

## 現行UI/UXへの批判的見直し（v2.1で解消する構造問題）
- **核が埋もれている**：ゴール・問い・次の一手が、メタ6項目とイベント一覧の中に
  同格で並び、開いた瞬間に「このPJは何で、いま何を考えているか」が読めない。
- **画面が多すぎる**：PJ5件に対し、ダッシュボード3ゾーン＋詳細3タブ＋取り込みページ。
  タブを行き来しないと全体が掴めない。
- **書くのが重い**：入力がモーダルフォーム経由で項目が多い。「1行書いて閉じる」ができない。
- **壁打ちに持ち出せない**：壁打ちしようとするとPJ情報をあちこちから拾って貼る必要があり、
  読ませる文書量が多い。壁打ちの起動コストがPJ思考の頻度を下げていた。

## 思想（v2.1）
- Project OS＝プロジェクトを**考える場所**。記録は考えた副産物として残る。
- **PJの核＝3行**：「ゴール」「現在の問い」「次の一手」。すべてのUIはこの3行に奉仕する。
- 設計基準は3つの数字：**核が10秒で読める／ムーブが10秒で書ける／壁打ちへ1コピーで持ち出せる**。
- 空白期間は正常な状態（考え中）。停滞を催促しない。
- Spreadsheetは主戦場から外す。共有は「共有用エクスポート」で書き出す（読み取り専用の想定）。

# 変更1：画面構成の刷新（タブ廃止・2画面に集約）

## ホーム＝PJカード一覧（旧ダッシュボード3ゾーンを吸収）
- PJごとに1枚のカード。カードに表示するのは：
  **PJ名／核3行（ゴール・現在の問い・次の一手）／最終ムーブからの経過（「N週」・事実表示のみ）／
  接近中の未来分岐バッジ（14日以内のみ・「{分岐名} あとN日」）**
- カード一覧の最上部に「今どこを押すか」1行帯：優先度＝分岐が近い→次の一手が古い→問いが長期停滞。
  旧TOP3の役割をこの1行に縮約する（3件並べない。1件だけ）。
- 旧「危険シグナル」ゾーンは廃止し、該当情報（期限超過・危険温度感等の既存データ由来）は
  各カード上の小バッジに吸収。ゾーンとして独立させない。
- カードクリックでPJ詳細へ。

## PJ詳細＝1画面スクロール（3タブ廃止）
上から順に：
1. **核3行**（大きく表示。クリックでその場インライン編集。モーダルを開かない）
2. **クイック追加**（入力欄1つ＋種類4ボタン。ボタンを押したら即保存＝送信を兼ねる。
   日付は自動で今日。分岐のみ任意の日付欄を出す）
3. **ムーブタイムライン**（新しい順。1ムーブ＝1行〜2行表示。種類は小さな色ラベル）
4. **折りたたみ（既定で閉じる）**：旧イベント一覧／詳細メタ（前提条件・成功条件・注意論点・
   論点メモ）／シートURL（📊閲覧ボタンのみ）
- 「概要／分岐点／記録」タブは廃止。分岐はタイムライン内で色分け＋未来分岐のみ核3行の直下に
  1行で予告表示（「⚡ {分岐名} あとN日」）。

## 取り込みページ
- PROJECT-IMPORT貼り付け画面のみに簡素化。シート取り込みUIはメニューから撤去
  （コードはレガシーとして残してよい）。

# 変更2：入力項目の最小化【書く量の削減】

- **新規PJ作成＝PJ名のみ**。ゴールすら必須にしない（後から核のインライン編集で書ける）。
- **ムーブ＝本文＋種類ボタンだけ**。担当・対象・施策・温度感・状態などの列は新規入力に一切出さない
  （既存データの表示互換のみ残す）。
- ムーブは4種：**決定／学び／分岐／次の一手**。
  「次の一手」は1PJにつき常に0〜1件（新しい一手を入れたら前の一手は自動で履歴化し、核3行と同期）。
- 「現在の問い」の更新もムーブ扱いで履歴化（旧い問いはタイムラインに自動で残る）。
- モーダルは原則全廃。例外は削除確認と共有エクスポートの項目選択のみ。

# 変更3：壁打ちコンテキスト出力【読む量の削減・v2.1の要】

壁打ち時に読ませる文書量を最小化するため、「壁打ちへ持っていく」ボタンを新設する。

## PJ単体版（PJ詳細とホームのカードに設置）
ワンタップでクリップボードにコピー。内容と分量：
```
【PJ】{PJ名}
ゴール：{1行}
現在の問い：{1〜2行}
次の一手：{1行}
接近分岐：{あれば1行}
直近の動き：
- {日付} {種類}：{本文}（最大5件・新しい順）
```
**目安400字以内**。これを超える場合はムーブ件数を削って収める。
壁打ちセッションはこのコピーだけを読めば開始できる、が完成条件。

## 全PJ横断版（ホームに設置）
全PJの「核3行＋接近分岐＋最終ムーブ経過」のみ。ムーブ本文は含めない。
**全体で1画面（目安800字）以内**。PJ横断の壁打ち・月次レビュー用。

# 変更4：アラートの転換
- **廃止**：期日切れの催促アラート（更新の目的化の駆動源）
- **維持**：未来分岐の接近表示（14日以内・カードバッジと核直下の予告）
- **停滞**：「最終ムーブからN週」の事実表示のみ。色・警告トーン・催促文言を使わない。

# 変更5：PROJECT-IMPORT（壁打ち取り込み）
Reflect OSの ---REFLECT-IMPORT--- と同型のパーサ（表記ゆれ・空行に寛容）：
```
---PROJECT-IMPORT---
PJ: {プロジェクト名（部分一致で解決。曖昧なら選択UI）}
決定: {本文}
学び: {本文}
分岐: {本文} @{YYYY-MM-DD（任意）}
次の一手: {本文}
問い: {現在の問いを更新する場合のみ}
---END---
```
各ラベル0件〜複数件。「問い:」「次の一手:」は核3行に同期し、旧値は履歴化。

# 変更6：共有用エクスポート（前田さんPJ対応）
- PJ詳細に「共有用に書き出す」：含める項目をチェックボックスで選択→
  (a)整形テキスト（コピー用）(b)TSV（シート貼り付け用）
- 内輪メモ（問い・詳細メタ）は既定でオフ。

# データ・互換の注意
- localStorage `pos_v4` のキー名・既存フィールド（name等）を変えない。
- 既存 projects/events/forks/records/メタ6項目を破壊しない。
- ムーブは既存構造に自然にマップできるなら既存配列を使い、無理なら新配列を追加
  （実コードを見て判断し、報告に明記）。ムーブに createdAt を必ず持たせる（将来の週次集計用）。
- JSONエクスポート/インポートに新データを含める。旧形式読込は自動移行。

# 実装フェーズ【各フェーズでコミット＆push・構文検証（node --check / esbuild）】
- **Phase 1**：核3行＋PJカードホーム＋詳細1画面化（タブ廃止・折りたたみ）＋クイック追加＋新規PJ最小化
- **Phase 2**：壁打ちコンテキスト出力（単体版・横断版）＋PROJECT-IMPORT＋アラート転換＋「今どこを押すか」1行帯
- **Phase 3**：共有用エクスポート＋シート取り込みメニュー撤去＋モバイル最終調整
コミットメッセージに「project-os: v2 Phase N」を含める。

# 受入条件
1. 既存PJ・既存データ（events/forks/records/メタ）が消えない
2. ホームを開いた瞬間、全PJの核3行と経過が読める（スクロール1画面以内・PJ5件時）
3. PJ詳細にタブがなく、核→クイック追加→タイムラインの順で1画面
4. 新規PJ作成の必須項目がPJ名のみ
5. ムーブ記録が「本文入力→種類ボタン」の2操作で完了する（モーダルなし）
6. 「壁打ちへ持っていく」で単体版400字以内・横断版800字以内がコピーされる
7. PROJECT-IMPORT貼り付けでムーブが該当PJに入り、問い・次の一手が核に同期する
8. 期日切れ催促アラートが存在しない／停滞表示が催促トーンでない
9. 未来分岐の接近がカードと詳細に出る
10. 共有用エクスポートで選択項目のみの整形テキストとTSVが出る
11. JSON保存・読込で新データも復元できる
12. コンソールエラーなし・モバイル幅で崩れない・リロード後も状態維持

# 報告形式
変更ファイル／ムーブのデータ構造（既存配列へのマップか新配列か）／画面構成の最終形／
壁打ちコンテキスト出力の実文字数サンプル／アラートの変更内容／テスト結果／残る制約。
不明点は既存コードから合理的に判断し、実装を止める場合のみ質問を1つ。
