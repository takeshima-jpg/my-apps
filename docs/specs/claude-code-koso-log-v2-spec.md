## 背景（なぜ）

構想見直しCowork（隔週）が「気づき・判断・統合・派生」を出すが、現行の構想ログには受け止める場所がない。取り込み（`parseAiText`／`registerAiInput`）は新規作成専用・1回1件で、既存構想の更新は Chrome経由の直接書き換えしか道がない。
あわせて、現行の `saveItem()` は編集時に項目オブジェクトを丸ごと差し替えるため、新しい項目を足しても編集のたびに消える。ここも直す。

## 1. データ構造（`kouso_backlog_v1` の各要素）

既存項目はすべて維持。以下を**任意項目**として追加する（無ければ無いものとして動く）。

| 項目 | 型 | 構想(G) | 試し(E) | 内容 |
|---|---|---|---|---|
| `goSign` | string | ○ | × | GOサイン＝「やる／やらないを分けるもの」1行 |
| `origin` | `{kind, date, note}` | ○ | × | kind ∈ `'種'`／`'壁打ち'`／`'1day'`／`'本人'`／`'取り込み'`。date は `YYYY/MM/DD` |
| `createdAt` | string `YYYY/MM/DD` | ○ | ○ | 生まれた日 |
| `relations` | `[{kind, id}]` | ○ | × | kind ∈ `'派生元'`／`'統合先'`／`'関連'` |
| `log` | `[{date, kind, text, src}]` | ○ | ○ | kind ∈ `'気づき'`／`'判断'`／`'統合'`／`'派生'`／`'PJ化'`／`'見直し'`。src ∈ `'本人'`／`'取り込み'`。**新しいものを末尾に push**（表示は新しい順） |
| `projectId` | string | ○ | × | PJ化したときの Project OS 側 id（引けたとき） |
| `projectName` | string | ○ | × | PJ化したときの Project OS 側 PJ名 |

**status**：`STATUSES` に `'PJ化'` を追加 → `['検討中','待機','実行中','PJ化','完了','廃棄']`。
- HOME（`renderHome`）の除外条件に `'PJ化'` を追加（`status!=='廃棄'&&status!=='完了'` → `'PJ化'` も除外）
- 一覧（`renderList`）では表示する（フィルタで選べる）
- バッジ色：`.badge-PJ化` を追加（既存の `badge-完了` と同系の落ち着いた色でよい）

**既存データの移行**（`load()` 内・冪等）
- 実行前に `kouso_backup_v2migration_YYYYMMDD` へ `kouso_backlog_v1` の生文字列を退避（既に同名キーがあれば作らない）
- `createdAt` が無い要素：構想は `review`（あれば）、無ければ `'2026/04/22'`（実データの最古レビュー日）。試しは親構想の `createdAt`
- `log`／`relations` が無ければ `[]`、`origin` は作らない（無いまま）
- 移行で項目の値は一切変えない。`review` も触らない

## 3. 画面

### 3-1. HOME（`renderHome`）
- 各カードの `purpose` の下に `goSign` があれば **「GOサイン：…」** を1行（薄い色・空なら出さない）
- 既存の「実行単位なし」→「試しなし」
- 件数バッジ（`home-priority-count`）は既存のまま（増やさない）

### 3-2. 一覧（`renderList`）— 構想の詳細（開いたとき）
`detailFields` に追加：
- `{label:'GOサイン', value:k.goSign}` を「目的/概要」の直後に
- 由来：`origin` があれば「由来：🌱種 10/12」「由来：壁打ち 10/16」の1行（kind が `'種'` のときだけ 🌱 を付ける）
- 関連：`relations` があれば小さなチップ「派生元 G03」「統合先 G05」「関連 G01」。クリックでその構想を開く（`expandedLog.add(id)` → `renderList()` → `scrollIntoView`）
- 記録：`log` を新しい順に、`m/d 種類｜本文` で表示（**最大5件、それ以上は「すべて見る」で展開**）
- 記録のクイック追加：記録の上に1行入力＋2ボタン **「気づき」「判断」**（Project OS のクイック追加と同じ作法）。押すと `{date:today(), kind, text, src:'本人'}` を push、`review`＝今日、保存、再描画。空文字は無視
- 最終レビューの行は既存のまま
- 一覧カードの閉じた状態（ヘッダー）には、**最新の記録1行**を `log-title` の下に薄く出す（あれば。`text` は 40字で省略）
- PJ化した構想は、詳細に「→ Project OS『{projectName}』」の1行（リンクにはしない。文字だけ）

### 3-3. 編集モーダル
- 「GOサイン」欄（`f-gosign`・text・構想のみ表示）を「目的/概要」の下に追加
- **`saveItem()` の差し替えを修正**：`items[idx] = data` を `items[idx] = {...prevItem, ...data}` にし、`goSign` を `data` に含める。`origin`／`createdAt`／`relations`／`log`／`projectId`／`projectName` はモーダルでは編集しないので、そのまま引き継がれること
- 新規作成時は `createdAt: today()`、`log: []`、`relations: []`、`origin: {kind:'本人', date: today()}`
- ステータスを `'PJ化'` にして保存したとき：log に `{kind:'PJ化', text:'→ Project OS', src:'本人'}` を自動追加。`projectName` は、`localStorage['pos_v4']` を読めて `title`／`name` が構想のタイトルと一致するPJがあればその名前と id を入れる（読めない・一致しないなら空のまま。**pos_v4 には書かない**）

### 3-4. 取り込む（`renderAiImport`／`registerAiInput`）
- 説明文と書式例を §4 の KOSO-IMPORT に差し替え（旧書式も受け付ける旨を1行）
- ボタンは「登録」1つ（1段階・プレビューなし）
- 「登録」の直前に `kouso_backup_lastimport` へ `{items, archives, at}` を退避（1世代・毎回上書き）
- 登録後のトーストに結果の要約：「G03 更新（GOサイン・記録2件）／G06 新規／E15 新規／G02→G05 統合」。長ければトーストは件数だけにし、同じ要約を取り込み画面の `ai-parse-status` に残す
- 取り込み画面の下部に小さなリンク **「直前の取り込みを元に戻す」**：`kouso_backup_lastimport` があれば表示。押すと確認なしで items／archives を戻し、保存、「戻しました」トースト、リンクは消える（退避キーは削除）
- 読めないブロックがあれば、そのブロックの先頭行を「読めませんでした：■ 構想 G0X …」と `ai-parse-status` に出し、**他のブロックは適用する**

## 4. KOSO-IMPORT の仕様

### 4-1. 書式（Cowork が出す・本人が貼る）

```
【KOSO-IMPORT】
■ 構想 G03
タイトル：危機管理コンサルの民主化
目的/概要：福利厚生サービスにして間口を広げる
成功条件：（変更なし）
GOサイン：法人の福利厚生担当が「危機管理」を買う言葉があるか
実行トリガー：
前提条件：（空にする）
戦略優先順位：B
ステータス：検討中
由来：壁打ち 2026-10-16
関連：派生元 G01
関連：関連 G05
記録：気づき｜lawroom.mirai-law.jp/worker/ は「従業員の個人問題」を会社が買う型。危機管理は会社の問題なので買い手が違う
記録：判断｜まず1社に「福利厚生として」の反応だけ聞く

■ 構想 新規
タイトル：JIPDECと協賛して経産省に働きかける
目的/概要：…
GOサイン：…
戦略優先順位：B
由来：壁打ち 2026-10-16

■ 試し 新規　親：G03
タイトル：顧問先1社に福利厚生の枠で反応を聞く
目的/概要：…
成功条件：「検討する」か「違う」かの言葉が取れる

■ 試し E07
ステータス：完了
記録：判断｜「福利厚生では買わない。BCPの枠なら話は聞く」

■ 統合：G02 → G05
理由：同じ買い手・同じ売り物だった

■ 廃棄：G04
理由：…
学び：…

■ PJ化：G01 → 3AHD2030構想
```

### 4-2. 解析の規則

- 先頭行が `【KOSO-IMPORT】` のときだけ新パーサ。無ければ旧 `parseAiText`（新規作成・互換維持）
- ブロックは行頭 `■ ` で区切る。種類は `構想`／`試し`（`実行` も同義として受ける）／`統合`／`廃棄`／`PJ化`
- `■ 構想 G03`／`■ 試し E07` ＝ **更新**。`■ 構想 新規`／`■ 試し 新規　親：G03` ＝ **新規**（試しの新規は親必須。無ければそのブロックは「読めませんでした」）
- 項目行は `キー：値`（全角・半角コロン両対応）。受け付けるキーと対応：
  `タイトル`→title／`目的/概要`（`目的・概要`／`概要`／`目的`）→purpose／`成功条件`→success／`GOサイン`→goSign／`実行トリガー`（`トリガー`）→trigger／`前提条件`（`前提`）→prereq／`戦略優先順位`（`優先順位`／`優先度`）→priority（先頭1字をS/A/B/Cに）／`ステータス`→status（`STATUSES` にある値のみ。それ以外は無視）／`由来`→origin／`関連`→relations（追記）／`記録`→log（追記）
- **更新の原則**：
  - 値が空、または `（変更なし）` → その項目は触らない
  - 値が `（空にする）` → 空文字にする（goSign／trigger／prereq／purpose／success のみ。title は空にできない）
  - それ以外 → 上書き
- `由来：{kind} {YYYY-MM-DD}` → `origin = {kind, date:'YYYY/MM/DD'}`。kind は `種`／`壁打ち`／`1day`／`本人`。既に origin がある構想では**上書きしない**（由来は変わらないため）。新規で由来行が無ければ `{kind:'取り込み', date:today()}`
- `関連：{kind} {ID}` → relations に追記。同じ `{kind,id}` が既にあれば入れない。ID が存在しなければ無視
- `記録：{kind}｜{本文}` → `{date:today(), kind, text, src:'取り込み'}` を push。kind が一覧外なら `'気づき'` 扱い。**同じ kind＋text（前後空白除去）が log の全件にあれば入れない**（同じ出力を2回貼った対策。2026-10-26 訂正：当初「直近3件」としたが、4行以上のブロックを2回貼ると全部二重になる設計ミスだったため全件に。claude-code-import-record-dedupe-spec.md が正）。区切りは `｜`（全角）と `|` の両方
- **統合** `■ 統合：G02 → G05`：G02 の status を `'完了'`、relations に `{kind:'統合先', id:'G05'}`、G02 の log に `{kind:'統合', text:'→ G05 に統合（理由：…）'}`、G05 の log に `{kind:'統合', text:'G02 を統合（理由：…）'}`。G02 配下の試しは**動かさない**（親は G02 のまま）。アーカイブには入れない
- **廃棄** `■ 廃棄：G04`：status `'廃棄'`、archives に `{id,title,priority,type,reason,learn,date:today()}`（既存 `confirmDiscard` と同じ形）。理由が無ければそのブロックは「読めませんでした」（廃棄理由は必須）
- **PJ化** `■ PJ化：G01 → {PJ名}`：status `'PJ化'`、`projectName`＝PJ名、log に `{kind:'PJ化', text:'→ Project OS「{PJ名}」'}`。`pos_v4` を読めて同名PJがあれば `projectId` も入れる。pos_v4 には書かない
- 更新・新規・記録追記があった**構想**は `review`＝今日。試しの更新では親の review は変えない
- 新規の構想は `genId('構想')`、試しは `genId('実行')`、`createdAt`＝今日、priority は構想＝指定（無ければ 'A'）、試し＝親から継承
- 1回の貼り付けで複数ブロック・同じIDへの複数ブロックも可（順に適用）
- 全ブロック読めなければ「【KOSO-IMPORT】の中に読めるブロックがありません」。1つでも適用できれば退避→適用→要約

## 5. 壁打ち用コピー（小さく）

一覧のヘッダー（フィルタバーの右）に **「📋 壁打ち用」** ボタンを1つ。押すとクリップボードへ：

```
【構想ログ 現在地 YYYY/MM/DD】
G03｜B｜危機管理コンサルの民主化｜GOサイン：…｜最新：10/16 判断｜まず1社に…
G05｜A｜…
```
- 対象：status が `検討中`／`待機`／`実行中` の構想（PJ化・完了・廃棄は除く）。優先順位順
- 1構想1行、GOサインが空なら「GOサイン：未設定」、記録が無ければ最新は省略
- 全体 800字を超えたら、C → B の順に行を落として収める
- 詳細を開いた構想の `log-actions` にも「📋 この構想」：タイトル／目的／GOサイン／試し（ID・タイトル・状態）／記録 直近3件、400字以内

## 6. やらないこと

- 期限・次回見直し日・「N日見ていません」・未処理バッジ・件数の警告を**足さない**
- `pos_v4` ほか他OSのキーへの書き込み
- Drive 連携
- `type` の値・ID 体系・`kouso_backlog_v1`／`kouso_archive_v1` のキー名の変更
- 旧書式（【構想】＋【実行単位】）の廃止
- 編集モーダルからの log／relations／origin の編集（記録はクイック追加、関連・由来は取り込みから）

## 7. 受入条件（playwright で実描画）

1. 既存データ（構想5・試し14・review 04/22）を入れた状態で開く → 表示が従来どおり、`createdAt` が補完され、`kouso_backup_v2migration_*` が1つだけ作られる。再読み込みで二重に作られない
2. 編集モーダルで GOサインを入力して保存 → 保存される。**続けて別の項目を編集して保存しても GOサイン・log・origin・relations が消えない**
3. 記録のクイック追加（気づき／判断）→ log に追加、review が今日、一覧ヘッダーに最新1行が出る、詳細で新しい順
4. KOSO-IMPORT：§4-1 の例をそのまま貼る → G03 が更新（成功条件は不変・前提条件は空・GOサイン設定・由来は既に origin があれば不変・関連2件・記録2件）、G06 新規（由来＝壁打ち 2026/10/16）、E15 新規（親 G03・priority 継承）、E07 完了＋記録、G02 完了＋統合先 G05・双方に統合の記録、G04 廃棄＋アーカイブ1件、G01 PJ化＋projectName。トーストに要約。`kouso_backup_lastimport` が作られる
5. 同じ KOSO-IMPORT をもう一度貼る → 記録が二重に入らない、関連が二重に入らない、G06／E15 がもう1件できる（新規は新規として扱う＝仕様どおり。要約にその旨が出る）
6. 「直前の取り込みを元に戻す」→ 4 の前の状態に戻る、リンクが消える
7. 存在しないID・理由なし廃棄・親なし試しを含む貼り付け → そのブロックだけ「読めませんでした」、他は適用
8. 旧書式（【構想】＋【実行単位】）を貼る → 従来どおり新規作成される
9. ステータス PJ化 → HOME から消え、一覧に残り、フィルタで選べる、詳細に「→ Project OS『…』」
10. 壁打ち用コピー：横断が 800字以内、単体が 400字以内（クリップボードの文字列を検証）
11. 「実行」の文字が画面上に残っていない（データの値 `'実行'` は残る）
12. スマホ幅（375px）で詳細・取り込み画面が崩れない。コンソールエラー 0。`node --check` 相当の構文検証 OK
13. Task OS の全OSバックアップ・復元（`kosoLog.items`／`archives`）で新項目が往復する（collect/restore はキー単位なので変更不要のはずだが、往復後に log が残ることを確認）
