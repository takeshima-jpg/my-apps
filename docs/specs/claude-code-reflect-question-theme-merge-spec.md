## 背景（なぜ）

11/2 に REFLECT-UPDATE の `■ 統合：問い A, B → 新規「…」` で、**重点**の問い「成果がなぜ出たのかを、本人が自分の言葉で語れるようにするには、何を聞けばいいか？」と**候補**の問い「答えを渡さず、本人が外へ動き、構想を広げ続ける状態をどうつくるか？」を1本にした（新しい問い `mvyhm2uimzvv9i1173a`）。結果：
1. 新しい問いが**候補**になった（`tkMergeQuestions` は常に `status:'candidate'`・2649行）。重点が1本減った
2. テーマが統合元のテーマの寄せ集め（`themeIds` の和）になり、本人が決めた「挑戦の環境づくり」（`mq10lp0zmj707kwem3d`）にならなかった。既にある問いのテーマを受信箱から付け替える書き方も無い

## 1. `■ 問い {実ID}` に「テーマ：」

- `テーマ：{テーマの実ID か題名の完全一致}` → `themeIds:[そのID]`（置き換え）、`noTheme` は外す
- `テーマ：なし` → `themeIds:[]`・`noTheme:true`
- 外したテーマ（`detached:true`）・存在しないテーマ → そのブロックだけ「読めませんでした：…」
- summary：「問い {ID} テーマ（仲間づくり→挑戦の環境づくり）」
- 同じテーマなら変更なし（冪等）。退避・「直前の更新を元に戻す」の対象
- （`■ 実験 {実ID}` にも同じ `テーマ：` を足す。実験の `themeIds` を同じ規則で置き換え）

## 2. 統合で状態とテーマを引き継ぐ（画面の統合モーダルと REFLECT-UPDATE の両方）

**既定の引き継ぎ（`tkMergeQuestions`／`tkMergeExperiments` で）**
- 問い：統合元に**重点**が1本でもあれば、新しい問いは**重点**。無ければ候補（統合元は `merged` になるので、重点の数は増えない＝上限に当たらない）
- 実験：統合元に**実験中**（`active`・決定検証を除く）が1本でもあれば、新しい実験は**実験中**。無ければ候補
- テーマ：統合元の `themeIds` の和から、**外したテーマ（`detached`）を除く**

**REFLECT-UPDATE の統合ブロックで上書きできるキー**
```
■ 統合：問い {A}, {B} → 新規「…」
理由：…
テーマ：{実ID か題名}（または なし）
ステータス：重点
```
- `テーマ：` があれば和ではなくその1つ（`なし` は空＋`noTheme`）
- `ステータス：` があればそれ（問い＝候補・重点、実験＝候補・実験中）。重点・実験中で上限に当たる場合は、既存の更新と同じく**そのブロックだけ保留**（統合元が merged になって空く分は数に入れてから判定）
- 冪等の判定（既に同じ題名の統合先へ統合済みなら何もしない）は今のまま。ただし既に統合済みのときに `テーマ：`／`ステータス：` があれば、統合先にそれを当てる（「変更なし」ではなく直す）
- 画面の統合モーダルにも「テーマ」の選択欄（既定＝上の和の先頭、「テーマなし」も選べる）を足す

## 3. 変えないこと

- 統合元を `merged`＋`mergedIntoId` で残すこと、実験の付け替え、仮説の結合
- 既に統合済みのデータはさかのぼって直さない（`mvyhm2uimzvv9i1173a` はリフレクト見直し担当が `■ 問い` で直す）

## 4. 受入条件（playwright。単体・`?inbox=1`・手貼り）

1. `■ 問い {ID}`＋`テーマ：挑戦の環境づくり` → `themeIds` が置き換わる。`テーマ：なし` → 空＋noTheme。外したテーマ → そのブロックだけ読めない。再適用で変化なし
2. `■ 実験 {ID}`＋`テーマ：` も同じ
3. 重点＋候補を統合 → 新しい問いは重点（重点の数は変わらない）。候補＋候補 → 候補
4. 実験中＋候補の実験を統合 → 実験中
5. 統合ブロックに `テーマ：` → その1つだけ。`ステータス：重点` で重点が上限 → そのブロックだけ保留
6. 統合済みの同じブロックを `テーマ：` 付きで再送 → 統合先のテーマが直る
7. 画面の統合モーダルでテーマを選べ、重点の引き継ぎも同じ
8. 「直前の更新を元に戻す」で戻る。375px・コンソールエラー0・構文検証OK・SW版上げ
