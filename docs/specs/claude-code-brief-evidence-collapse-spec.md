# Claude Code 実装依頼書：Briefの根拠ブロックを既定折りたたみにする

作成日：2026-08-18
対象：`brief-viewer/index.html` の `markdownToHtml()`、および `1day/index.html` の同名関数（**両方**）
作業前に `git pull`。

## 問題

Morning Briefの本文に、Coworkの選定プロセス（選定理由・重複チェック・差し替え候補など）が
そのまま載っており、毎朝読むべき行動指示が埋もれている。実測で本文の約6割が根拠部分だった。

根拠は検証時には必要なので削除ではなく**畳む**。
併せてCowork側の出力規約も変更する（`docs/prompts/cowork-feedback-brief-slim-2026-08-18.md`）。
本依頼書はViewer側＝**保険と可読性の担保**であり、Cowork側の変更が先に効く前提で作る。

## 修正内容

`markdownToHtml()` に、根拠ブロックを `<details>` で畳む処理を追加する。

### 記法（Cowork側と合わせた規約）

```
─根拠─
・選定理由：…
・14日重複：…
・差し替え第1候補：…
─根拠ここまで─
```

- 開始マーカー：行全体が `─根拠─`（前後の空白は無視）
- 終了マーカー：行全体が `─根拠ここまで─`、**または次の見出し行（`#` `##` `###`）が現れた時点**
  （終了マーカーが無くても壊れないこと。Cowork側の出力揺れを吸収する）
- マーカー間の行は既存のmarkdown変換をそのまま通し、`<details><summary>根拠を見る</summary>…</details>` で包む
- `<details>` は**既定で閉じる**（`open` を付けない）

### 実装上の注意【厳守】

- `markdownToHtml()` は入力を `&` `<` `>` でエスケープしている。
  マーカー判定は**エスケープ後の文字列に対して**行うか、判定を先に済ませること。
  生成する `<details>` タグはエスケープ対象に含めない
- リスト（`<ul>`）の途中で `<details>` を開くとHTMLが壊れる。
  マーカー行に到達したら **`inList` を閉じてから** `<details>` を開くこと。閉じるときも同様
- `brief-viewer` と `1day` の `markdownToHtml()` は「同一」とコメントで明示されている。
  **必ず両方に同じ変更を入れる**（片方だけの変更は禁止）
- マーカーが1つも無いBriefは**従来どおり**に描画されること（後方互換）

### スタイル

`<summary>` は控えめに。既存のトーン（静かなUI）に合わせ、文字サイズを本文より小さく・色は淡く。
折りたたみが存在することが分かれば十分で、目立たせない。

## 検証
- 構文検証（node --check）
- マーカー付きBrief → 根拠部分が畳まれ、既定で閉じている・クリックで開く
- 終了マーカーが無く次の見出しが来るBrief → その見出しの手前で正しく閉じる
- マーカー無しの旧Brief → 表示が従来と一致する（後方互換）
- 根拠ブロック内にリスト・リンクがある場合もHTMLが壊れない
- brief-viewerと1dayの両方で同じ結果になる
- スマホ幅で崩れない・コンソールエラーなし

## コミット
「brief-viewer/1day: Brief本文の根拠ブロック（─根拠─〜）をdetailsで既定折りたたみ表示にし、
毎朝読む行動指示を前面に出す（マーカー無しBriefは従来どおり・両OSのmarkdownToHtmlを同期）」
