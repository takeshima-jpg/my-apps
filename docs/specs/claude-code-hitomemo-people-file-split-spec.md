# Claude Code 実装依頼書：ヒトメモの取り込みを人物/接点の2ファイルに分離

作成日：2026-08-18
対象：`hitomemo/index.html` の `gdriveAutoImportHitomemo()` 周辺
作業前に `git pull`。

## 背景（診断済みの事実）
- 現行の取り込み元は `10_日次データ/daily-contacts.json`（7/26再編済み。旧 `aix-drafts/aix-hitomemo.json` はフォールバック）
- 起動時オートインポート・people取り込み・接点更新・名前正規化の重複排除は**すべて実装済み**
- ヒトメモにDrive書き込み処理は**存在しない**（「アプリが書き戻して上書き」という旧診断は誤り）
- 真の問題：**Coworkが人物入りファイルと接点入りファイルを同名で別々の回に書く**ため、
  最新1件採用＋ファイル単位のmodifiedTime冪等キー（AIX_LAST_KEY）により人物版が影に隠れて読まれない
  （実例：荏原剛・田口琢也の2名が未登録に反映されない）

## 修正内容

### ① 読み込みを2ファイルに分ける（どちらもCowork出力・アプリは読むだけ）
- **人物**：`10_日次データ/daily-people.json` — `{"people":[ <人物プロファイル文字列>, ... ]}`
- **接点**：`10_日次データ/daily-contacts.json` — `{"contacts":[...]}`（現行のまま・追補Eで30日ローリング化予定）

`gdriveAutoImportHitomemo()` を、両ファイルをそれぞれ検索→取得→適用する形にする。
- people系：`daily-people` を検索（同名複数は現行同様に最新1件）。無ければ旧名 `aix-hitomemo` を
  aix-drafts直下からフォールバック（移行期の保険・現行踏襲）
- contacts系：`daily-contacts` を検索（現行ロジック維持）
- 片方が無くてもエラーにせず、あるほうだけ適用する

### ② 冪等キーをファイル別に分ける
`AIX_LAST_KEY` を people用と contacts用の2キーに分離（例：`aix_last_people` / `aix_last_contacts`）。
既存キーからの移行は不要（初回に両方読み直しても people は名前重複スキップ・contacts は鮮度ガードで冪等）。

### ③ パーサは既存を流用・手動と共通化の確認
`__hitomemoImportPeople` の既存パーサをそのまま使う。手動「メモからインポート」が同じパーサを
通っているか確認し、別実装なら共通化する（ラベル仕様：氏名（ふりがな）／所属・役職・事業／
価値観・大切にしていること／核となる一言／関わり方タイプ／次に渡す経験／誕生日／経歴・背景／
個性・傾向／印象・洞察／メモ。先頭行【人物プロファイル】はスキップ。関わり方タイプは
育成/共同成長/相互学習/維持の4値に正規化・括弧補足は無視。tier/stageは付与しない）。

### ④ 変更しないこと【厳守】
- 接点更新ロジック（`__hitomemoApplyContacts`：鮮度ガード・名寄せ・changeLog冪等）
- 未登録への追加動作・トースト表示
- GDrive未ログイン時の手動インポートフォールバック
- Driveへの書き込みは**追加しない**（読み取り専用のまま）

## 検証
- 構文検証（node --check）
- daily-people.json（people入り）とdaily-contacts.json（contacts入り）が両方ある → 両方適用される
- peopleだけ／contactsだけ → あるほうだけ適用・エラーなし
- 同じpeopleファイルを2回読んでも未登録が増えない（名前重複スキップ）
- contactsの冪等（既知エントリ・古い日付）が従来どおり
- 旧名aix-hitomemoフォールバックが生きている
- 手動「メモからインポート」貼り付けで同じ結果になる

## コミット
「hitomemo: 取り込みを人物(daily-people)/接点(daily-contacts)の2ファイルに分離。
冪等キーをファイル別化し、人物ファイルが接点ファイルの影に隠れて読まれない問題を解消
（両方Cowork出力・アプリは読み取り専用のまま）」
