# ヒトメモ接点の自動更新：Coworkパッチ ＋ ヒトメモ側受け口（2部構成）

> ✅ Part B 実装済み 2026-07-16 ・ `dccd83c`（hitomemo/index.html）
> 🕒 Part A はCoworkプロンプト（v5系本体）への適用待ち。下のSTEP 4.7ブロックをそのまま転記する

目的：カレンダー・1dayログにある接点（会食・打合せ等）を毎朝自動検知し、ヒトメモの
「最終接触日」と「接点ログ」を自動更新する。「30日以上接触なし」アラートの誤報（実際は会っている）を解消。

設計方針（2026-07-16 再設計）：
- 接点は `aix-hitomemo.json` の**トップレベル `contacts` 配列（構造化JSON）**で渡す。
  `people` 配列（新規人物のテキストメモ）とはキーで分離し、テキスト方言の誤判定を排除する。
- ヒトメモ側の受け口は **name / date / type / note の4キーしか読まない**ため、
  stage / isActive / engagementType / プロフィール欄の混入は**構造的に不可能**。
- ヒトメモ側が完全に冪等（鮮度ガード＋changeLog自体を重複台帳化）なので、
  Cowork側は**重複管理・前日出力の記憶が不要**。毎朝、窓の中の接点を無条件に全部出せばよい。
- 検知の窓は**直近14日**。ヒトメモを毎日開かなくても、開いたときに全部追いつく
  （2日窓だと3日開けなかった日の接点が固定名ファイルの上書きで永久に失われるため拡大）。

## Part B：ヒトメモ側の受け口（hitomemo/index.html 小改修）

hitomemo の自動取込（aix-hitomemo.json → 起動時 gdriveAutoImportHitomemo）に
contacts 経路を追加する：

1. **受付フィールド**：`data.contacts` を新設の `__hitomemoApplyContacts` で処理。
   更新するのは既存人物の lastContactDate と changeLog **のみ**。新規人物は作らない。
   changeLog エントリは `{ date, type:'接点', text:'{type}：{note}', source:'自動検知' }`。
2. **鮮度ガード**：lastContactDate は「既存より新しい日付のときのみ」更新（Cowork側ルールとの二重防御）。
   過去日の接点でも changeLog には追記する（未記録の事実は履歴として残す）。未来日は無視。
3. **ステージ保護**：contacts 経路は name / date / type / note の4キーしか読まないため、
   stage / isActive / engagementType / personType / プロフィール欄は構造的に更新不可能。
   people 経路（新規人物）・手動AI更新読込・手動メモインポートは無改変。
4. **重複防止**：新しいlocalStorage台帳は作らず、**changeLog自体を台帳にする**
   （source='自動検知' かつ date・text が一致するエントリが既にあれば追記しない）。
   データ本体に乗るため端末をまたいでも冪等。既存の hitomemo_aix_imported（名前台帳）は
   新規人物の復活防止という本来の役割のまま温存（接点には使わない）。
5. **照合**：手動AI更新と同じ規則（lxNormName 部分一致→複数候補なら完全一致1件のみ採用）。
   曖昧・未登録はスキップ（Cowork側がbriefに提示する）。
6. **トースト**：「🤝 接点を自動更新：N人（◯◯さん 他）」。新規取込と同時のときは併記。

### 検証
- テスト用 contacts（新しい日付・古い日付・同姓複数・stage混入・未来日・家族を含む）で：
  新しい日付のみ lastContactDate 更新／古い日付はログのみ／混入フィールド無視／
  再実行で二重追記なし（冪等）／曖昧名スキップ／家族更新可。
