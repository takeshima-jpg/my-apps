# Claude Code 実装依頼書：Lectica日次スキップの自動pause化（手動スキップ操作の廃止）

作成日：2026-08-18
対象：`shot-task-os/index.html` の `lxSkip()` とLectica Shotの表示、`task-os/index.html`（同期経路の確認のみ）
作業前に `git pull`。

## 問題

やらなかった日のLectica Shotが期限超過として残り続け、竹嶋が**手で1件ずつ「スキップ」を押して閉じている**。
2026-08-15には18件をまとめて処理していた（休み・繁忙で触れなかった期間の分）。

これは2つの害がある。

1. **復帰コスト**：休み明けに開くと、まず溜まった処理という「罰」から始まる。戻る動機が削られる
2. **データの汚染**：18件すべてが `insight:'スキップ（実施できず）'` の同一文言。
   「見た上で合わなかった」と「そもそも触っていない」が同じログになり、出題の当否が判定できない

## 修正内容

### ① 期日を過ぎた未完了Lectica Shotを自動pauseにする

Shot OS読み込み時（`render()` 前の初期化）に、次の条件を満たすShotを自動処理する：

- `category === 'Lectica'`
- `dueDate < 今日`
- `status` が `'todo'` または `'doing'`

処理内容：
- `status` を `'pending'`（既存の保留ステータス）に変更する
- `lecticaAutoPaused: true` を付与する（手動保留と区別するため）
- `updatedAt` を更新する
- **`lectica_experiment_logs_v1` にログを書かない**（後述）

冪等：既に `pending` のものは再処理しない。1回のロードで複数日分をまとめて処理してよい。

### ② 自動pauseはログを残さない【重要】

現行の `lxSkip()` は保留ログを1行書いているが、**自動pauseでは書かない**。
理由：全件同一文言のログは分析価値がゼロで、実施率の分母は生成済みShotの履歴から算出できるため。

**14日連続回避への影響**：`autoGenLecticaShot()` の `recent` 判定は
「logsの実験ID」＋「直近14日のLectica Shotのmemoから拾う実験ID」の両方を見ている。
Shotは削除せず `pending` で残すため、**recent判定は現状のまま壊れない**。この点を実装時に必ず確認すること。

### ③ 手動スキップボタン（`lxSkip`）を撤去する

自動pauseが入れば手動操作は不要。`lxSkip()` 関数と「スキップ」ボタン（`ab-skip`）を撤去する。
関数本体はコメントアウトではなく削除してよい（復活が必要なら本依頼書を参照）。

**能動的に「この実験は自分に合わない」と判断した場合の受け皿は、
Reflect OSの実験マスタ側にある既存の「見送る」→3択（合わない／忘れた／余力なし）を使う。**
日次のスキップと実験そのものの見送りは別物であり、混ぜない。この役割分担を撤去箇所のコメントに1行残すこと。

### ④ 自動pause済みのLectica Shotは期限超過セクションに出さない

自動pause（`status==='pending'`）は既存の集計から外れるはずだが、
期限超過バナー・カウントに混入しないことを実機で確認する。混入する場合は除外する。

## 検証
- 構文検証（node --check）
- 昨日以前の未完了Lectica Shotを用意 → ロードで `pending` かつ `lecticaAutoPaused:true` になる
- 同じ状態で再ロードしても変化しない（冪等）
- `lectica_experiment_logs_v1` に新規行が増えていない
- 完了済み（done）のLectica Shotは変化しない
- Lectica以外のカテゴリのShotは一切変化しない【厳守】
- 自動pause後に `autoGenLecticaShot()` の14日連続回避が従来どおり効く
- 期限超過バナー・件数に自動pause分が入らない
- 「スキップ」ボタンが消えている・コンソールエラーなし
