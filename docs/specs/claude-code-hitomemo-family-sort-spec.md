# Claude Code 実装依頼書：ヒトメモに「家族」独立カテゴリ ＋ 並び替え機能

## 背景
関係ステージ（記録のみ/つながり/信頼を深める段階/経営パートナー）は**経営パートナー路線の人**に適用するもの。
家族はパートナー路線ではなく、ステージ・稼働・次に渡す経験・昇格トリガー・鮮度アラートを当てはめるのは
意味的に不適切。よって家族を独立カテゴリとして分離し、パートナー形成ロジックから外す。
あわせて一覧の並び替え機能を追加する。

## 前回依頼との差分（重要）
UI改善v2（claude-code-hitomemo-form-ui-spec-v2.md）で「関わり方タイプに『家族』を追加」としたが、
**それは取り消し**。家族は関わり方タイプの選択肢ではなく、下記の独立カテゴリで扱う。
（もしv2で関わり方タイプに家族を追加済みなら、その選択肢は撤去。ただし既存データ保護は維持）

## 変更対象
hitomemo/index.html（＋AI更新パーサ）。既存データは壊さない。

## 1. 「家族」独立カテゴリ（personType のような区分軸）
- 人物に「区分」フィールドを持たせる（例 `personType`: 'partner'（既定）/ 'family'）。
  - 'partner'（既定）：従来どおり関係ステージ・稼働・次に渡す経験・関わり方タイプ等をすべて表示。
  - 'family'：**経営パートナー形成セクションを丸ごと非表示**にする。
    （関係ステージ・🤝稼働中・関わり方タイプ・次に渡す経験・昇格/鮮度・進捗カウントの対象外）
- 詳細画面に「区分」トグル/セレクト（パートナー形成 / 家族）を上部に置く。
  家族を選ぶと、経営パートナー形成の入力群が隠れ、家族向けに必要な項目（名前・続柄・メモ・
  最終接触日・変化タイムライン程度）だけ残る。続柄（妻/子/父/母/兄弟…）の自由入力欄があると良い。
- **家族は経営パートナー進捗(X/10)に数えない**、鮮度アラート・昇格トリガー検知の母集団からも除外。
- 移行：旧roleStageや旧値が「家族」の人物は personType='family' に寄せてよいか、confirmで件数提示して承認後に実行
  （自動判定が不確実なら移行はせず、ユーザーが手動で家族に切り替える運用でも可。その場合はその旨を報告）。

## 2. 一覧の並び替え機能
- 一覧画面に並び替えセレクトを追加。並び替えキー：
  - 関係ステージ順（経営パートナー→信頼を深める段階→つながり→記録のみ）
  - 最終接触日（新しい順／古い順）
  - 名前（あいうえお順）
  - 🤝稼働中を上に
  - 更新日（新しい順）
- 既定は「関係ステージ順」。選択状態は localStorage に保存し次回も維持。
- 家族カテゴリは一覧で別扱いにできると良い（フィルタ「家族のみ/パートナー形成のみ/すべて」）。難しければ並び替えのみでよい。

## 3. AI更新パーサ・SU同期の追従
- AI更新読込：personType（'family'）の受付に対応。家族の人物は経営パートナー系フィールドを更新しない。
- Social Universe同期：家族カテゴリの人物のステージ等を触らない（前回同様、SUはstageを上書きしない方針を踏襲）。

## 4. データ保護
- personType 未設定の既存人物は 'partner' 扱い（従来表示）。
- 旧タグ・旧値が残っていてもエラーにしない。GDrive/JSONバックアップに personType が含まれること。

## 検証
- esbuild --jsx=transform で構文検証
- 区分=家族に切替→経営パートナー形成セクションが隠れる／進捗(X/10)・鮮度アラートの対象外になる
- 並び替え各キーが正しく動作し、選択が保存される
- 家族の人物がAI更新でステージを書き換えられない
- 既存人物（personType未設定）が従来どおり表示・編集・保存できる
