## 背景（なぜ）

- VISION は 10/27 に「安心があるから挑戦できる、挑戦できるから成長する、成長するから安心できる。1人ではなく、特性を生かしたチームで、四方良しの未来を選ぶ。」に変わった。ところが各OSには**旧 VISION「守りの総合支援を通して…」と原則5つ（共創を含む）が10ファイルに埋め込まれている**
  - Reflect のホーム（669行付近）・`VD`（1048行付近）、task-os（713）、project-os（3875）、launcher（267）、hitomemo（1040）、100list（494）は `myapps_vision` を読まず、埋め込みだけを出す
  - routine-os の `renderVision`（2163行付近）は `myapps_vision` を読んだ後も、埋め込みの配列 `all` を出している
  - 1day・shot-task-os・social-universe は `myapps_vision` を読むが、無いときに旧文が出る
- `myapps_vision`（Reflect の「VISION設定」で保存）はバックアップに入っていない（Reflect の自前スナップショット 2862行だけ）
- 本人決定：OS の VISION は `myapps_vision` 1つを正本にし、どのOSもそこから出す。年末ゴールの層は置かない（戦略目標に統一）
- テーマ（在り方の軸）と VISION のつなぎ方（11/3 本人決定）：
  - ①**並びで見せる**：Reflect のホームを VISION → テーマ → 重点の問い → 実験中 の順にする
  - ③テーマごとに**「今いちばん足りない言葉」を1つ**選ぶ（当てはまる言葉ではなく足りない言葉。全部当てはまる問題を避けるため）。選択肢は**原則と指針の7つ（成長・愛・誠実・寛容・確信・仲間・健康）**。行動に近く具体的に選べるため
  - ④テーマごとに **VISION の循環（安心→挑戦→成長→安心）のどこで止まっているか**を1つ選ぶ
  - ③④は半期の VISION 見直しで選び直す。印を付けて分類するためのものではないので、一覧の絞り込みや集計には使わない

## 1. `myapps_vision` を正本にする（全OS）

### 1-1. データの形（後方互換）
```
{
  "vision": ["安心があるから挑戦できる、挑戦できるから成長する、成長するから安心できる。",
             "1人ではなく、特性を生かしたチームで、四方良しの未来を選ぶ。"],   // 1要素以上
  "principles": [{"title":"成長","text":"…"}, …],
  "directions": [{"title":"確信","text":"…"}, …],
  "words": ["成長","愛","誠実","寛容","確信","仲間","健康"],       // 新設：③の選択肢（§3）
  "cycle": ["安心","挑戦","成長"],                                  // 新設：④の循環の順（§3）
  "updatedAt": "2026-11-03",                                        // 新設：保存した日
  "source": "VISION設定" | "VISION見直し" | …                        // 新設：どこから保存したか
}
```
- `words` が無い古いデータは、`principles` と `directions` の `title` を順に並べたもので補う（コードに言葉を埋め込まない）。`cycle` が無ければ `["安心","挑戦","成長"]`。補うだけで保存し直さない
- 文の中身はコードに埋め込まない。初回の中身は竹嶋さんが「VISION設定」に貼る（メンテナンス担当が JSON `VISION設定_貼り付け用_2026-11-03.json` を用意済み）

### 1-2. 各OSの読み方
- 10ファイルすべて、VISION・原則・指針の表示は `myapps_vision` から作る。**旧文の埋め込み（`VISION_DATA` の中身・`VD`・`all`・`_vTexts`・`VISION_DEFAULT`・launcher の `tab-vision`・Reflect ホームの固定文）を外す**
- 読み方は1つの小さな関数にそろえる（各ファイルに同じ形で置く。例 `loadVisionShared()` → 上の形 or null）
- `myapps_vision` が無い・壊れているとき：VISION の帯・ピルは**出さない**（旧文で埋めない）。Reflect のホームだけ、VISION の場所に薄い1行「VISION は『VISION設定』で入れられます」（リンク）
- 日替わりで1つ出すOS（routine・shot・hitomemo 等）の並びは今のまま（VISION→原則→指針を順に、日付で1つ）。中身だけ正本から
- CLAUDE.md 7行目の旧 VISION の埋め込み指示を「VISION は `myapps_vision` から読む（埋め込まない）」に直す

### 1-3. バックアップ・復元
- Task OS の全OSバックアップ（`collectAllOSData`）に `myappsVision: jGet('myapps_vision')` を足す。復元と、復元前の退避対象（`RG_KEYS`）にも足す
- CLAUDE.md のデータ契約に `myapps_vision` の形（§1-1）を追記

## 2. VISION を受信箱から直せるようにする（VISION見直し担当用）

- 受信箱（`targetOS: reflect`）に新しいブロック `---VISION-UPDATE---` を受ける。Reflect が処理する
```
---VISION-UPDATE---
VISION：安心があるから挑戦できる、…四方良しの未来を選ぶ。
原則：成長｜未来を作るために…
原則：愛｜…
指針：確信｜…
言葉：成長、愛、誠実、寛容、確信、仲間、健康
---END---
```
- 書いた項目だけ置き換える（`VISION：` は複数行可＝配列、`原則：`/`指針：` はどれか1行でも書けば**その種類を全置換**、`言葉：` は読点区切りで全置換）。`cycle` は受信箱では変えない
- 置き換える前の `myapps_vision` を退避キー `myapps_vision_prev`（1世代）に入れる。Reflect の「直前の更新を元に戻す」で戻せる
- 読めなかった行は summary に「読まなかった行：…」。`importInbox.log` の summary に「VISION を更新しました（原則4・指針3・言葉7）」のように出す
- 「VISION設定」の JSON 貼り付けは今のまま残す（`words` 等の新しい欄も貼れる・無ければ既定）。整形プロンプトの出力フォーマットに `words` を足す

## 3. Reflect のテーマに「足りない言葉」と「止まっている所」（③④）

### 3-1. データ（テーマ）
```
visionLink: {
  lacking: "仲間",            // ③ myapps_vision.words から1つ。未選択は無し
  stuck:   "挑戦→成長",        // ④ "安心→挑戦" | "挑戦→成長" | "成長→安心" | "流れている"
  note:    "…",               // 任意。ひとこと（なぜそう見たか）
  setAt:   "2026-12-20",
  by:      "画面" | "VISION見直し"
}
```
- 選び直したら前の値はテーマの記録に1行残す：「（VISION）足りない：仲間→寛容／止まっている所：挑戦→成長→成長→安心（2026-12-20）」
- 外したテーマ・完了のテーマでも値は消さない（表示しないだけ）

### 3-2. 画面
- テーマのカード（ホームと探求ボード）に、重点の問いの行の上に小さく1行：
  `足りない：仲間 ／ 止まっている所：挑戦→成長`（薄い文字。値が無ければ**行ごと出さない**。「未設定」や催促は出さない。赤は使わない）
- テーマの編集画面に2つの選択（ボタン型。③は `words` の数だけ＋「選ばない」、④は4つ＋「選ばない」）とひとこと欄。選択肢は `myapps_vision.words` から作る（コードに言葉を埋め込まない）
- `words` が変わって、選んでいた言葉が選択肢から消えた場合は、値はそのまま表示し、編集画面で「（今の VISION に無い言葉）」と添える

### 3-3. REFLECT-UPDATE
- `■ テーマ` に2つのキーを足す：`足りない言葉：仲間`、`止まっている所：挑戦→成長`（`流れている` も可）、`ひとこと：…`
- 足りない言葉が `words` に無いときは、そのキーだけ読まずに summary に出す（テーマのほかの変更は通す）
- `by:'VISION見直し'` は、受信箱の item の `source` が VISION見直し のとき。それ以外は `'画面'` ではなく `'受信箱'`

### 3-4. 使わないこと
- 一覧の絞り込み・並べ替え・件数・バッジには使わない（分類の印ではないため）
- 戦略目標には付けない（戦略目標の VISION とのつながりは、四半期の戦略目標見直しの問いで扱う）

## 4. Reflect のホームの並び（①）

- 上から：**VISION（1行・タップで原則・指針）→ テーマ（カードに §3 の1行）→ 重点の問い → 実験中（R番号）**
  - 今は「現在の重点」を VISION より上に置いている（UIスプリント1 A-4 の `focusSlot`）。これを VISION の下に移す
  - VISION は本文1行（`vision[0]`。2要素以上あれば「▶ 全文を見る」）＋「▶ 原則・指針を見る」。今の折りたたみ部品（`vision-expand`/`vision-detail`）を使う。見出しの「VISION 2026」は「VISION」に（年を固定しない）
  - 「VISIONを編集」ボタンは今の場所のまま
- 重点の問いは、つながるテーマの下に寄せて見せる（テーマ→その重点の問い→その実験中。ゲシュタルトの近さ）。テーマにつながらない重点の問いは最後にまとめる
- 375px で VISION が2行を超えるときは2行で切って「…」、タップで全文

## 5. 変えないこと

- 「VISION設定」の画面と貼り付け保存（§2 の追記以外）
- 探求ボードの上限（重点3・実験中は重点1本につき5本）、R番号、統合、保管
- Morning Brief が読むバックアップ要約の既存キー（`reflectOS.themes[]` に `visionLink` が増えるだけ）
- 戦略目標の定数 `STRATEGY_GOALS`（5ファイル）

## 6. 受入条件（playwright・11/3 のバックアップ相当）

1. `myapps_vision` が無い状態で全10ファイルを開く → 旧文「守りの総合支援を通して」が**どこにも出ない**（`grep` でもコードに残っていない。CLAUDE.md も）。Reflect のホームに案内1行
2. 「VISION設定」に `VISION設定_貼り付け用_2026-11-03.json` を貼って保存 → 10ファイルとも新しい文が出る。原則に「共創」が出ない。`words` を消した JSON を貼っても、足りない言葉の選択肢は原則・指針の7つになる
3. Task OS のバックアップに `myappsVision` が出て、復元で戻る
4. 受信箱の `---VISION-UPDATE---`（`言葉：` だけ）→ `words` だけ変わり、ほかは同じ。`myapps_vision_prev` に前の値、「元に戻す」で戻る。読めない行は summary に出る
5. テーマの編集画面で「足りない：仲間」「止まっている所：挑戦→成長」を選ぶ → カードに1行。選び直すと記録に前の値1行。値が無いテーマは行が出ない
6. REFLECT-UPDATE `■ テーマ` の `足りない言葉：`／`止まっている所：` が入る。`words` に無い言葉はそのキーだけ保留で summary
7. Reflect のホームが VISION → テーマ（その重点の問い・実験中）→ テーマにつながらない重点 の順。375px・コンソールエラー0
8. 構文検証・pre-commit 通過・各OSの SW 版上げ（task-os は BUILD_VER も）
