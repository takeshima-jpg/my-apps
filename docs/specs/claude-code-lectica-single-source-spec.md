# Claude Code 実装依頼書：Lectica出題の選定者を一本化（Task OSのランダム生成を廃止）

作成日：2026-08-18
対象：`task-os/index.html` の `autoGenLecticaShot()`
作業前に `git pull`。

## 問題（2026-08-18に実機で確認）

Lecticaの出題を決める主体が2つ並走している。

- **Cowork（Brief）**：統合棚卸しの週割当から選ぶ。使う場面・完了条件まで文脈込みで指定する
- **Task OS**：`autoGenLecticaShot()` がその場で**ランダムに選ぶ**（文脈ゼロ）

`aix_lectica_pending` による差し替えは実装済み（`857c826`）だが、成立するには
①当日付のpendingが存在 ②「AIタスク読込」を実行 ③既存がランダム由来かつ未完了、が全部揃う必要がある。
ひとつでも欠けるとランダムのまま残る。

実測：同日にBrief=L028／Task OS実表示=L019／BriefがTask OSと認識している値=L035、と3つに割れた。
竹嶋が日中に目にするのはTask OS側（文脈ゼロ）であり、これが実験のスキップ多発の主因と見ている。

## 修正内容

**Coworkの提案を唯一の選定者とし、Task OSは写すだけにする。**

`autoGenLecticaShot()` から**ランダム選定の分岐を撤去する**。

1. 当日付の有効な参謀提案（`aix_lectica_pending`・日付一致・`usable`）が**ある**場合
   → 従来どおりShotを生成する（`lecticaSource:'sanbo'`）
2. 参謀提案が**ない**場合
   → **何も生成しない**（return 0）。Lectica Shotは当日存在しない状態が正
3. 既存Shotがある場合の差し替えロジックは**現状のまま維持**する
   （random由来かつ未完了のときだけ後着提案で差し替え。移行期に残る旧randomデータを救うため残す）

### 変更しないこと【厳守】
- 差し替えの冪等性（同じ提案を再取り込みしても変化しない）
- 手動追加・完了済み・sanbo由来のShotは上書きしない
- `lecticaSource` フィールドの意味と付与ルール
- 14日連続回避のロジック自体は残す（提案が最近使用済みの場合の判定に引き続き使う）。
  ただし**提案を却下する方向には使わない**：参謀提案がある日は連続回避に関わらず必ず採用する
  （選定責任はCowork側にあり、Task OSは判定しない）

### 催促しない
Lectica Shotが無い日に「今日の実験がありません」等の警告・空カード・プレースホルダを**出さない**。
何も無い日は何も表示しない（設計憲章：signal over noise／催促しない）。

## 検証
- 構文検証（node --check）
- pendingあり → 従来どおりsanbo由来のShotが1件生成される
- pendingなし → Shotが生成されない・コンソールエラーなし・HOMEに空要素が出ない
- 既存random Shotあり＋pendingあり → 従来どおり差し替わる（冪等）
- 完了済み・手動追加のShotは差し替わらない
- リロード後維持
