# Claude Code 実装依頼書：取り込みの「記録：」重複判定の修正（KOSOLog・Reflect）と G05 の重複掃除

作成日：2026-10-26（メンテナンス担当。構想見直し担当の報告「G05 の記録4行が二重」を受けて）
対象：`koso-log/index.html`、`reflect-os/index.html`
土台：main `3260088`。作業前に `git pull`。

## 起きていること（原因はコードで確認済み）

- KOSOLog の G05「竹嶋家100年の計」に、10/17 の KOSO-IMPORT の「記録：」4行が2組（log 8件）入っている（10/26 22:06 のバックアップ `kosoLog.items`）
- 重複判定は `kiPushLog`（1616行）で**「直近3件に同じ text があれば入れない」**。1ブロックに記録が**4行以上**あると、2回目の貼り付けで1行目は直近3件（＝1回目の2〜4行目）と一致せず追加され、以後も1行ずつずれて全部追加される。**依頼書（`claude-code-koso-log-v2-spec.md` §4-2「直近3件」）の設計ミス**で、実装はそのとおりに動いている
- 同じ判定を Reflect の REFLECT-UPDATE の「記録：」（`reflect-os` 1377行 `notes.slice(-3)`）にも書いてしまっているので、同時に直す
- G08 の記録3行が二重にならなかったのは、3行以下だったため

## 直し方

### 1. 重複判定を「直近3件」から「全件」に（両OS）
- KOSOLog `kiPushLog`：`item.log` の**全件**に対して `kind` と `text`（前後空白を除いて比較）が同じものがあれば入れない
- Reflect の notes 追記（1377行）：`o.notes` の**全件**に対して同じ比較
- 同じ本文を別の日に意図して2回残したい、というケースは想定しない（記録は「言った」ことの履歴で、同文の再記録に意味がないため）。必要なら本人が画面のクイック追加で入れる
- 表示側の `slice(-3)`（1274行・2217行＝直近3件の表示）は**そのまま**

### 2. 既存の重複の掃除（KOSOLog・起動時1回・冪等）
- 起動時に1回だけ、全構想・試しの `log` から **`kind`＋`text` が同じ要素の2つ目以降**を取り除く（最初の1件を残す。`date` は最初の1件のもの）
- 実行前に `kouso_backup_logdedupe_20261026` へ退避（同名キーがあれば作らない）。実行済みフラグ `kouso_logdedupe_done`
- 取り除いた件数が1件以上ならトーストで1回だけ「記録の重複 n 件を整理しました」。0件なら何も出さない
- Reflect の notes は REFLECT-UPDATE が今日入ったばかりで重複は無いはずなので、掃除処理は作らない（念のため実データで `notes` の重複が0件であることを確認して報告）

### 3. 依頼書の訂正
- `docs/specs/claude-code-koso-log-v2-spec.md` §4-2 と `claude-code-reflect-update-block-spec.md` §1 の「直近3件」を「全件」に書き換える（Claude Code が docs 側も直してよい。本依頼書を正とする）

## 受入条件
1. KOSOLog：記録5行の KOSO-IMPORT を2回貼る → 2回目は1件も増えない（summary に「記録 0件（重複）」）。改行や全角「｜」の違いで別文面と見なされない（`text` は区切り「｜」の後ろ・前後空白除去で比較）
2. KOSOLog：起動時に G05 の重複4行が1組になり、G08 は変わらない。`kouso_backup_logdedupe_20261026` が1つ、再読み込みで二度走らない。実データ相当で掃除件数を報告
3. Reflect：REFLECT-UPDATE で記録5行を2回 → 2回目は増えない
4. 既存データのほかの項目は変わらない。構文検証・コンソールエラー0・SW版上げ（Reflect）
