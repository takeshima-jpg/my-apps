## §2 直すところ（`hitomemo/index.html`）
### 2-1 受信箱の block に `stages` を足す
```
{"stages":[{"name":"山田太郎","stage":"つながり"},{"name":"鈴木花子","stage":"記録のみ","isActive":false}]}
```
- `people`・`contacts` と同じ block に並べてよい。処理の順は **people → stages → contacts**（新しく足した人のステージも同じ block で決められるように）
- `stage` は 記録のみ／つながり／信頼を深める段階／経営パートナー のどれか。それ以外はその1件を飛ばす
- `isActive`（任意・true／false）があれば 🤝 稼働中の印も直す。無ければ触らない
- 名前の合わせ方は `__hitomemoApplyContacts` と同じ（`lxNormName`・部分一致で1人に決まるか、完全一致が1人）
- 反映は今の `__hitomemoUpdateStage` と同じ結果にする（ステージが変わったら changeLog に「ステージ: 旧 → 新」を1行。source は「受信箱」）。同じステージなら何もしない（何度取り込んでも増えない）
- **階層（`tier`）が「未登録」の人のステージを決めたときは、画面の「📥 未登録」で階層を決めたときと同じ結果になるようにして、未登録の一覧から外れるようにする**（どの値にするかは、今の画面の動きに合わせる。報告に書く）
- 家族（`personType: family`）の人は、ステージを変えない（飛ばして summary に出す）

### 2-2 名前が合わなかった人を summary に出す
- `contacts`・`stages` で名前が合わなかった（誰にも当たらない・複数に当たって決まらない）ものを数え、summary の末尾に「／名前が合わない：山田、鈴木」（最大5人・超えたら「ほか n人」）を足す
- 名前が合わないものが1件でもあっても、ほかが反映できていれば `ok:true` のまま（保留に残さない。直すのは次の週次で参謀が聞く）
- 今の summary「人物 n件・接点 n件（うち既存 n件はスキップ）」に「・ステージ n件」を足す

## §4 確かめること（Code 自身の確認・試しのデータで）
1. `{"stages":[{"name":"（今いる人）","stage":"つながり"}]}` を受信箱経由（`?inbox=1`）で取り込むと、その人のステージが変わり、changeLog に1行足される。もう一度取り込んでも増えない
2. 階層が「未登録」の人のステージを決めると、「📥 未登録」の一覧から外れる
3. `people` で足した新しい人に、同じ block の `stages` と `contacts` が効く
4. 名前が合わない接点とステージを混ぜた試しで、summary に「名前が合わない：…」が出て、ほかは反映される
5. 家族の人のステージは変わらない
6. `people`・`contacts` だけの block（今までの形）の結果が、直す前と同じ
