## 症状の要点

前回（8/19）は「ランダムが先勝ちして提案に置き換わらない」だったが、今回は**ランダムすら存在しない状態で、同期しても何も生成されない**。

## 有力仮説（優先順に確認してほしい）

1. **案A実装が「置き換え」のみで「新規生成」パスがない** 同期時ロジックが「当日のフォールバック由来Shotを探して、あれば提案で置き換える」だけだと、当日のLectica Shotが**0件**の場合（朝のランダムShotを手で削除した後／フォールバック未発動）に何も起きない。 → 同期時「当日Lectica Shotが0件 かつ 当日date一致の提案あり」なら**提案からShotを新規生成**するパスを追加する必要がある。  
2. **起動時フォールバックが発動していない** 8/21朝の起動時にランダムShotが出ていたか。出ていなければ、降格改修の副作用でフォールバック自体が死んでいる可能性。  
3. **複数行memoで生成処理が例外落ちしている** パッチXでmemoが実改行入りの複数行になった（8/21から本適用）。生成・保存・描画のどこかで例外→サイレント中断していないか。8/20（旧1行memoに近い形）までは提案受信自体は動いていた点と符合しうる。  
4. **読取先の取り違え** `gdFindDailyFile('daily-tasks','aix-tasks')` が確定仕様（①10\_日次データの`daily-tasks.json`最新createdTime優先→②無い時のみ直下旧名）どおりに動いているか。直下残骸は掃除済みなので、以後この経路の干渉は消える。

## 受け入れ確認（4点）

1. 当日のLectica Shotが0件＋当日提案ありでGDrive同期 → **提案からShotが新規生成される**  
2. フォールバックShot（lecticaSource='random'・未完了）がある状態で同期 → 提案で置き換わる  
3. 完了済みShotは置き換えない／同一提案の再同期で重複生成しない（冪等）  
4. memoに改行（\\n複数行）を含む提案で 1〜3 がすべて通る

## デバッグ支援のお願い

同期処理に1行だけconsoleログを足してほしい： `[lectica-sync] 提案date=…, experimentId=…, 当日Shot件数=…, 分岐=create|replace|skip(理由)` これがあれば次回不具合時にスクショ1枚で切り分けできる。

## 追補（2026-08-22 バックアップ解析で判明した決定的事実）

8/22朝のバックアップ（shotTaskOS全件）を解析した結果：

- **Cowork提案由来（lecticaSource='sanbo'）のShotは、7/30を最後に一度も生成されていない**（7/22・7/23・7/24・7/30の4件が最後。いずれも旧・直下aix-tasks.json時代）  
- その後に生成されたLectica Shotは **8/18の `lecticaSource:'random'` 1件のみ**。8/19以降はrandomもsanboも**ゼロ**  
- つまり「提案からShotを生成する経路（sanbo）」は**約3週間死んでいる**。8/19のL051・8/20のランダムは起動時フォールバックで、それも8/19以降のバックアップには残っていない（削除済み）

時系列との突き合わせ：

- 〜7/30：直下の `aix-tasks.json` を読んでsanbo生成が動いていた  
- 8/18〜：読取先が `10_日次データ/daily-tasks.json`（新名・最新createdTime）に移行  
- → **sanbo生成経路だけが旧読取先（または旧データ形式）のまま取り残されている**可能性が最有力。homeFocusCard等の新機能は動いているので、ビルド自体は最新

確認してほしい1点：提案からShotを生成/置換する関数が、`gdFindDailyFile('daily-tasks','aix-tasks')`（①10\_日次データのdaily-tasks.json最新createdTime→②無い時のみ直下旧名）と**同じ読取結果を使っているか**。同期処理の別経路が直下の `aix-tasks.json` だけを見ていると、直下は掃除済みのため「提案なし」と判定され、今回の全症状（置換もされない・新規も立たない）と完全に一致する。
