# 申し送り：Reflect OS 改修「意思決定検証の廃止」「取り込むをメニューの上へ」（Claude Code向け・2026-10-26）

作成：VISION見直し担当の設計チャット（竹嶋さんの決定 2026-10-26）
宛先：Claude Code（my-apps / Reflect OS）。メンテナンス（設計）チャット経由で貼る。

## 目的（なぜ変えるか）

- 意思決定検証：予測と答え合わせは「VISION見直し担当」（Cowork）のチャットで行い、予測帳（Drive）に記録する運用に決めた（竹嶋さんの言葉「意思決定検証の記録があなたと壁打ちで簡潔になるので、リフレクトOSの意思決定検証が不要になる」）。Reflect OSの「意思決定検証」は使わないので、メニューから外す。
- 取り込む：いちばん使う操作が「⇩ 取り込む」なので、サイドメニューの一番上に移す（竹嶋さんの言葉「一番使う項目が取り込むボタンなので上に持っていってほしい」）。

## 先に確認すること（推測で進めない）

1. Reflect OSの意思決定検証のデータ件数を確認する。2026-10-19時点のバックアップでは0件。0件なら表示と導線を外すだけでよい。1件以上あれば削除せず、アーカイブ側で読めるようにしてから導線を外す。
2. 「取り込む」の取り込みブロックの書式・動作は変えない（リフレクト見直し担当・VISION見直し担当が出す貼り付け用ブロックはこの書式に依存している）。位置を変えるだけ。
3. バックアップJSONの構造は変えない（意思決定検証のキーが空配列のまま残ってよい。他の担当がJSONを読むときに壊れないこと）。
4. 探求ボード・ログ・Lectica・アーカイブ・VISION設定の動作は触らない。

## 変更1：サイドメニューの並び

現在：ホーム／ログ／探求ボード／意思決定検証／Lectica／アーカイブ／VISION設定／取り込む
変更後：**取り込む**／ホーム／ログ／探求ボード／Lectica／アーカイブ／VISION設定

- 「⇩ 取り込む」を一番上に置く。見た目は他の項目と同じ部品で、アイコン（⇩）はそのまま。
- 「意思決定検証」の項目を外す。画面本体（ルート）は残してよいが、メニューからは消す。直リンクで開けるなら「この機能はVISION見直し担当の予測帳に移りました」と1行出す。
- 下の「JSON保存」「詳細（復旧用）」の位置は変えない。

## 変更2：ホーム画面

- ホームに意思決定検証への導線や件数表示があれば外す。
- その他は変えない（重点の問い・実験中・VISION 2026の表示はそのまま）。

## 画面の方針（竹嶋さんのUI10法則から）

- フィッツの法則：いちばん押す「取り込む」を、カーソルと親指が最初に届く一番上へ。サイズは他の項目と同じでよい（大きくしない）。
- ヒックの法則：使わない「意思決定検証」を外して、メニューを8項目から7項目に減らす。
- ヤコブの法則：並びを変えるだけで、項目の見た目・操作は今までどおり。新しい部品は作らない。
- ゲシュタルトの法則：「取り込む」を上に移したあとも、ホーム〜VISION設定の並び（見る→考える→設定）は崩さない。
- フォン・レストルフ効果：「取り込む」を一番上に置く以外の強調（色・太字・枠）は付けない。一つだけ違う位置にあることで十分。

## 変更しないこと

- 取り込みブロックの書式・取り込みの処理。
- 探求ボードのデータ構造、実践中の実験の上限（別件で5本への改修を予定。今回は含めない）。
- バックアップJSONの構造。

## 完了の確認

- サイドメニューの一番上が「⇩ 取り込む」で、押すと今までと同じ取り込み画面が開く。
- 「意思決定検証」がメニューに無い。
- バックアップJSONを出して、他のキーが今までどおり出ている。
- 配置が終わったら竹嶋さんがリフレクト見直し担当のチャットに「Reflect OSの意思決定検証は廃止。予測と答え合わせはVISION見直し担当の予測帳で行う」と1行伝える（リフレクト見直し担当の起動プロンプトに意思決定検証を読む記述があれば、その担当が自分で外す）。
