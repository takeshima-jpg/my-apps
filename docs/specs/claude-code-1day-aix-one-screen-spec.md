前提：main `83c824f`。本人決定（11/27）による。触るファイルは `1day/index.html`（＋ service-worker の版）。

## §1 経緯
- 11/24 から、Morning Brief が「まだ 1day に入っていない直近7日」の下書きを毎朝入れている。1日分は約400字・10行（できごと＋【感情記録】の候補）で、前より長い
- 本人（11/27）：「提案文の量が増えているので今のウィンドウだとスクロールしないと読めない」「スクロールせず読んで修正して保存ができるようにしたい」
- スクロールが要る理由：
  1. 画面が1列（`#aix-view` が最大 680px）で、満足度 → できごと → 感情のチップ → ゆみさんの負荷 → 与えた → 違和感 → フラグ → 保存 と縦に長い
  2. 「できごと」の textarea は、書き始めるまで中身に合わせて伸びない（`oninput` でしか高さを合わせていない）。欄の中でもスクロールが要る
  3. 数日分のカードが縦に並ぶ
- 本人決定（11/27）：下の §2〜§5 を入れる

## §2 並べ方（PC・窓の幅 900px 以上のとき）
1. **`#aix-view` の最大幅を 680px → 1200px** にする
2. **カードの中を2列にする**（保存済みでない日の、大きい形のカード）
   - **左の列（広い方）**：日付、「できごと」の textarea、その下に感情の補助（`kjBarHtml`）
   - **右の列（幅 320px ほど・固定）**：上から 今週は？（◎〇△×）／🏠 ゆみさんの負荷（はい・いいえ＋一言）／🤲 与えた（＋一言）／△ 違和感／フラグ／**「保存」「スキップ」**
   - 右の列は、左の列が画面より高くなったときも見えているように、上に貼り付ける（`position: sticky`）。**「保存」「スキップ」がいつも画面の中にある**こと
3. **「できごと」の textarea を、描いたときから中身が全部見える高さにする**（描いた直後と入力のたびに `scrollHeight` に合わせる）。最小 140px。上限は「窓の高さ − 上の見出し・タブ・カードの余白」で、それを超える長い日だけ欄の中でスクロールする（ページ全体のスクロールにしない）
4. **右の列のボタンを低くする**：満足度の4つ・「はい」「いいえ」・「与えた」を、高さ 34px ほどにする（今の `yl-btn`・`gv-btn` は 44px 以上。承認フォームの中だけ低くし、「＋記録する」の画面のボタンは変えない）。押せる幅は列いっぱいのまま
5. **感情のチップを1行に収める**ことは今回しない（今のまま折り返してよい）
6. 窓の幅が 900px 未満のときは、今と同じ1列の並び（左の列の中身 → 右の列の中身の順）にする。§3 のタブと §2-3 の高さ合わせは、狭いときも同じに動かす

目安：窓 1280×720 で、できごとが約400字・10行の日を開いたとき、**ページを縦にスクロールせずに、日付から「保存」まで全部見える**こと。

## §3 1日ずつ出す
7. 一覧の上に**日付のタブ**を横に並べる（下書きの並び順のまま。表示は「11/24（火）」の形。保存済みの日に足す下書き＝`append: true` は「11/20 に足す」）。**件数・バッジ・未読の印は出さない**。開いているタブだけ色を変える（`var(--accent)` の下線か背景。赤・オレンジにしない）
8. **開いているのは1日分だけ**。最初は一番左（いちばん古い日）を開く。タブを押すとその日に切り替わる
   - 切り替える前の日に書きかけ（できごと・違和感・一言メモ・選んだボタン）があっても、**切り替えて戻ったときに残っている**こと（タブごとにカードを作って出し入れする、で足りる。保存していない書きかけを localStorage に書く必要はない）
9. 「保存」「足す」「スキップ」の後は、**同じ位置の次の日（無ければ1つ前の日）を自動で開く**。下書きが無くなったら今の「未承認のドラフトはありません」
10. 保存済みの日に足す下書き（小さい形のカード）は、同じタブの並びに入れる。カードの中身は今のまま（1列・足す内容＋「足す」「スキップ」）
11. **ほかのタブ・受信箱から下書きが増えた・変わったとき**（今は `renderAixDraftList()` を呼んで全部描き直している所・2407・2413 付近と storage の聞き手）：**開いている日のカードと、書きかけのあるカードは作り直さない**。タブの並びだけ足し引きする。開いている日の下書きそのものが無くなったときだけ、§3-9 と同じに次の日を開く
12. 「保存」「スキップ」が並びの番号（`aixApproveByIdx(i)`・`aixDismissByIdx(i)`）で下書きを引いている所は、**日付で引く形にそろえる**（タブの出し入れで番号がずれて、別の日に保存しないように。依頼書16 の `aixAppendByDate` と同じ考え方）。選んだ状態を持つ `window._aixSat_i` などの変数も、日付ごとに持つ形にしてよい

## §4 保存まわり
13. **Ctrl＋Enter（Mac は ⌘＋Enter）で、開いている日を保存**する（大きい形は「保存」、小さい形は「足す」と同じ動き）。承認フォームが出ているときだけ効く。「＋記録する」の画面では今のまま
14. 保存したときの知らせは今の「✅ YYYY-MM-DD の記録を保存しました」のまま。その後 §3-9 で次の日が開く
15. 保存の中身（`aixApproveByIdx` がログに書くもの）は変えない

## §5 下書きの「違和感」を欄に入れておく
16. 下書きに `unease` が入っているとき、**右の列の「△ 違和感」の欄に最初から入れておく**（今は下書きの `unease` を承認フォームで読んでいない）。本人が直したり消したりできる。保存のときは今までどおり、欄に入っている文を使う
17. 下書きの `flags` は今までどおり読まない（フラグは本人が押す）

## §6 触らないもの
- ログに書く中身・下書きの書式（`aix_drafts`）・受信箱・Task OS
- 「＋記録する」の画面（見た目も動きも）
- ゆみさんの集計のカード、与えたの欄の決め（集計を作らない）
- 感情の補助（`kjBarHtml`）の動き
- スマホ幅の確認は不要（PC だけ。900px 未満で崩れないことだけ見る）

設計の根拠（UI心理学）：ミラーの法則・ヒックの法則（一度に見せるのは1日分。読む所と押す所を左右に分ける）／フィッツの法則（「保存」をいつも同じ場所・画面の中に置く。Ctrl＋Enter）／ゲシュタルトの法則（文章は左、短い選択は右にまとめる）／ヤコブの法則（欄の名前・ボタンの字・保存の動きは今のまま）／ピークエンドの法則（保存したら次の日が開き、最後は「ありません」で終わる）／損失回避（タブを切り替えても・ほかから下書きが増えても、書きかけを消さない。日付で引いて別の日に保存しない）／美的ユーザビリティ効果（右の列のボタンの高さをそろえる）。催促にしない：タブに件数・未読の印を付けない
