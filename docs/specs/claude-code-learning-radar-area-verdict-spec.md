# Claude Code 依頼書：学びレーダー「エリア違い」判定の追加

- 対象：`learning-radar/index.html`（my-apps）
- 起票：2026-10-18（Cowork）
- 関連：claude-code-learning-radar-check-spec.md §2（learning-check.json の定義）、追補A

## 1. 背景（竹嶋さんからのフィードバック）

学びチェックでは、対面のセミナーの開催日に「◎大阪」のような遠方の予定が入っていると「✕ 重複」と表示されていた。
しかし、これは時間が重なっているのではなく、**その日は東京にいないので会場に行けない**という状態。
竹嶋さんからの要望は「重複扱いというよりはエリアが違うので、エリア違いの表記が欲しい」というもの。

例：12/10(木)【品川区】事業承継セミナー。この日は「◎大阪」で、品川の会場には行けない。

## 2. 変更内容

### 2-1. 判定の種類（verdict）を1つ追加

learning-check.json の `checks[].verdict` に **`"area"`** を追加する。

| verdict | 意味 | 出す条件（Cowork側） |
|---|---|---|
| `area`（新規） | エリア違い | 対面またはハイブリッドで会場参加が前提の学び。その開催日に、東京近郊以外の終日予定（◎大阪・◎宇都宮・合宿など）がある |

例：

```json
{
  "url": "https://www.jigyousyoukei.co.jp/2026/09/56496/",
  "startDate": "2026-12-10",
  "title": "【品川区】事業承継セミナー（後継者ノート配布）",
  "verdict": "area",
  "label": "エリア違い：◎大阪の日",
  "detail": "12/10 は終日「◎大阪」、14:00〜18:00「◎帰京」。対面（品川区戸越）のため参加は難しい",
  "conflicts": ["12/10 ◎大阪（終日）"],
  "proposal": null
}
```

- オンラインの学びで遠方の日に当たる場合は、従来どおり `ok`（または該当する別の判定）。label には「大阪から参加可」などを書く。
- 遠方の日で、同じ時間に打合せもある場合は `area` を優先する（行けない理由として、場所のほうが根本的なため）。打合せは `detail` と `conflicts` に書く。

### 2-2. カード上の表示

- バッジは **「△ エリア違い」**。「✕ 重複」とは色を分ける（例：重複＝赤系、エリア違い＝橙〜黄系）。
  - フォン・レストルフ効果：「行けない理由が時間ではなく場所」とひと目で分かるよう、重複とは別の色にする。
  - ゲシュタルトの法則：バッジの形と位置は、既存の「◯ 空き」「✕ 重複」と揃える。
- バッジの横には、従来どおり `label` を表示する。

### 2-3. 互換性

- `verdict` が `"area"` の判定ファイルを、古い版のアプリで読んでも壊れないこと。
- 知らない verdict が来たときは、灰色の中立バッジ ＋ `label` を表示する。ついでに、この扱いを全体の既定動作にする。
- 絞り込みや件数の集計で「重複」をまとめて数えている箇所があれば、`area` は**重複とは別枠**にする（ない場合は対応不要）。

## 3. Cowork側の対応（参考・Claude Code の作業範囲外）

- 学びチェックの判定で `area` を出す。このアプリ側の変更が反映されるまでの間は、`verdict: "away"` のまま `label` を「エリア違い：◎大阪の日」にして出す。
- 「学び検討」カレンダーの説明欄にも「エリア違い」と書く（2026-10-18 から対応済み）。

## 4. 確認してほしいこと

1. 上の例の判定ファイルを取り込んだとき、12/10 のカードに「△ エリア違い　エリア違い：◎大阪の日」が出ること。
2. 既存の `ok` / `meeting` / `away` / `dinnerRule` などの表示が変わらないこと。
3. verdict に `"zzz"` のような知らない値を入れたとき、灰色バッジで表示され、エラーにならないこと。
