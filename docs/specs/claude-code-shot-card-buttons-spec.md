作成日：2026-11-02（メンテナンス担当。本人決定 11/2：どちらも A）
対象：`shot-task-os/index.html`（カードの操作ボタン・1515行付近）、`task-os/index.html`（HOME の実験の Shot の行・今日タブ・上部カード）
土台：main `6278081`。作業前に `git pull`。

## 背景（なぜ）

- 「やる」（`setToday`＝期日を今日に変える）が全カードで一番目立つ紫のボタンになっているが、**期日がもう今日のカード**と**実験の Shot**（最初から期日が今日。持ち越しも翌営業日の分として出る）では押しても何も変わらない
- 「保留（期日超過で自動pause）」は、押すと手で保留にするボタン。書き添えの「期日超過で自動pause」は実験の Shot だけの動き（`lxAutoPause`）で、ふつうのタスクには当てはまらず紛らわしい。実験の Shot は「後でやる／やってない」と自動の保留で足りていて、手で保留にすると結果が無いまま保留になり、参謀には「本人が選んでいない」に見える

## 直し方

1. **「やる」**：次のどちらかのときは出さない
   - `category:'Lectica'`（実験の Shot）
   - `dueDate` が今日（`getTodayKey()`）と同じ
   - それ以外（期日が先・期日なし・期日が過去）は今までどおり出す
2. **「保留」**：
   - 実験の Shot（`category:'Lectica'`）では出さない（保留中の実験の Shot に出る「未着手に戻す」はそのまま）
   - ふつうのタスクは、文言を **「保留」** だけにする（`title` の説明も外す）。動き（`changeStatus(id,'pending')`）は変えない
3. **目立つボタン**：「やる」を出さないカードでは、「完了」をいちばん前の目立つボタン（今の「やる」と同じ `ab-primary` の見た目）にする。「やる」を出すカードは今までどおり「やる」が目立つボタン
4. ボタンの並び：残ったボタンの順は今と同じ（やる → 完了 → 保留／未着手に戻す → 不採用 → 編集 → 削除）
5. **実験の Shot は、結果の3択を最初からボタンで出す**（本人追加 11/2）：
   - 未完了の実験の Shot（未着手・自動保留とも）では、「完了」の代わりに **「やった」「やってない」「後でやる」** の3つを並べて出す。押すとすぐ `lxApplyResult` で保存（3択のシートを開く1手を無くす。「やめる」は不要）
   - 「やった」を目立つボタン（`ab-primary`）、ほか2つは控えめ。赤は使わない
   - 自動保留の実験の Shot は、3つに加えて「未着手に戻す」も残す
   - 削除の3択、`lecticaDetail` が無い古い Shot の扱いは今までどおり
   - **Task OS の HOME**（行・今日タブ・上部カード）の実験の Shot も同じく、✓ の代わりに3つのボタン。HOME の実験の Shot からは **「↗ 翌日」を外す**（結果なしで翌日へ送ってしまい「後でやる」と重なるため）。ふつうの Shot の ✓・↗ 翌日はそのまま
   - 375px では折り返してよい（3つが1行に入らなければ2行）。ボタン44px以上

## 変えないこと

- `lxAutoPause`（期日超過の実験の Shot を自動で保留）、結果3択、削除の3択
- Task OS の HOME のふつうの Shot の操作（✓・↗ 翌日）
- 完了済みカードの「戻す」

## 受入条件（playwright）

1. 期日が今日のふつうのタスク：「やる」なし、「完了」が目立つ見た目、「保留」の文言
2. 期日が明日・期日なし・期日が過去のふつうのタスク：「やる」あり（今までどおり目立つ見た目）、「保留」の文言
3. 実験の Shot（未着手）：「やる」「保留」「完了」なし、「やった（目立つ）／やってない／後でやる」が最初から出て、押すとすぐ結果が保存される（シートは開かない）
4. 自動保留の実験の Shot：3つのボタンと「未着手に戻す」が出る、「保留」は出ない
4-2. Task OS HOME：実験の Shot の行に3つのボタン、✓ と「↗ 翌日」は無い。ふつうの Shot は今までどおり
5. 375px・ボタン44px以上・コンソールエラー0・構文検証OK・task-os の BUILD_VER・両OSの SW 版上げ
