## 背景（なぜ）

10/27 に VISION見直し担当が受信箱へ置いた Reflect 宛ての1件（`vision-20261027-02`）に、`【REFLECT-UPDATE】` の中で `■ 問い 新規` と書いた新しい問いが2件あった。REFLECT-UPDATE は「実IDで指して直す」だけで新規作成をしないため、2件とも「読めませんでした：■ 問い 新規（問いの実IDが見つかりません）」となり入らなかった（同じ本文の `■ 実験 R003` の記録は入ったので、受信箱では「済み」）。

構想ログ（KOSO-IMPORT）は `■ 構想 新規` で作れるので、担当が同じ書き方をするのは自然。新しい問いを【振り返り】で作ると、仮説・記録が一緒に入らず、振り返りログも1件増え、番号が分かってから直す2段階になる。**REFLECT-UPDATE に「新規」を足して、1回で入るようにする。**

## 1. 書式（追加分）

```
【REFLECT-UPDATE】
■ 問い 新規
題名：現状のリソースで…その基準を事前に持つ
ステータス：候補
仮説：…
記録：…

■ 実験 新規
題名：…
問い：{つなぎ先の問いの実ID}
ステータス：候補
場面：…
観察：…
期限：YYYY-MM-DD
記録：気づき｜…
紐づけ：S02 ②3AHD構想作成／PJ：s6n9vf1vgdx 3AHD2030構想
```

- 見出し行 `■ 問い 新規`／`■ 実験 新規`（「新規」は全角・前後の空白は既存と同じく寛容に）。`rfParseUpdate` で `op:'create'`
- キーは既存の更新と同じ（`RF_UQ_KEYS`／`RF_UE_KEYS`）。**題名は必須**（無ければそのブロックだけ「読めませんでした：…（題名がありません）」）
- `ステータス` 省略時は **候補**。問い＝候補・重点のみ受ける（解消・破棄で新規作成は「読めませんでした」）。実験＝候補・実験中のみ受ける
- 上限：`重点` で重点が `TK_MAX_FOCUS_Q`（3）に達している／`実験中` で実験中が `TK_MAX_ACTIVE_E`（5）に達している → **作らずに** そのブロックだけ `limits` に入れて保留（既存の更新と同じ文言・扱い。勝手に候補で作らない＝本人が入れ替えを決めてから再適用）
- 実験の `問い：` は既存の問いの実ID（無ければ「つなぎ先の問いの実IDが見つかりません」で読めない）。**同じ本文の中で直前に新規作成した問いへはつなげない**（実IDがまだ無いため。必要なら翌日 `■ 実験 {実ID}` で付け替え）
- 期限は YYYY-MM-DD（既存と同じ検査）
- `記録` は作成直後の `notes[]` に `rfPushNote` で入れる（種類｜本文。区切りが無ければ種類「記録」＝既存どおり）

## 2. 作るオブジェクト

- 問い：画面の「問いを追加」（2388行）と同じ形
  `{id:uid(), title, themeIds:[], status, hypothesis:'', sourceLogIds:[], mergedIntoId:null, createdAt, updatedAt, completedAt:null, notes:[]}`
- 実験：画面のフリー追加と同じ形（`expType` は付けない＝通常の実験）
  `{id:uid(), questionId:(指定 or null), title, themeIds:[], status, scene, observation, deadline, result:'', learning:'', sourceLogIds:[], createdAt, updatedAt, completedAt:null, notes:[]}`
- 保存は `tkSave`。作ったIDは `out.questionIds`／`out.experimentIds` へ（→ 受信箱・手貼りとも既存の `inboxAttachLinks` で `links` が付く。問いの `links.questionId` は付けない＝実験にだけ、は既存どおり）
- 作成前に退避（既存の `backup()` を1回）

## 3. 冪等（二重作成しない）

- 問い：`merged` 以外の既存の問いに **題名が同じ（前後空白・全角半角空白を除いて一致）** ものがあれば作らない。summary は「問い 新規『…』既にあります（{実ID}）」。そのブロックの `記録` は既存の問いの `notes` に重複判定つきで足す（取りこぼし防止）。仮説は既存が空のときだけ入れる
- 実験：同じく題名一致（`merged`・`expType:'review'` は除く）で作らない。扱いは問いと同じ
- 受信箱の `id` は共通部品が弾く（既存どおり）

## 4. 要約（summary）

- 「問い 新規『現状のリソースで…』（候補）」「実験 新規『…』（候補・問い q…）」のように、題名は先頭20字＋「…」
- 既存の更新ブロックの要約と同じ並びに入れる

## 5. 変えないこと

- 既存の `■ 問い {実ID}`／`■ 実験 {実ID}`／`■ 統合：…` の挙動、退避と「直前の更新を元に戻す」（新規作成も戻せる＝退避からの復元でそのまま消える）
- 【振り返り】→ `tkMigrate` で候補が生まれる従来の流れ
- 受信箱の「済み／保留」の判定（一部のブロックが読めなくても、ほかが入れば済み、は今回は変えない）
- ファイル先頭のコメント（1315行付近）の「新規作成はしない」を「新規は `■ 問い 新規`／`■ 実験 新規`」に書き換える

## 6. 受入条件（playwright。単体・`?inbox=1`・手貼りの3経路）

1. `■ 問い 新規`（題名・仮説・記録あり・ステータス省略）→ 候補の問いが1件、`hypothesis` と `notes` 1件が入る。同じ本文を再適用 → 増えない（summary「既にあります」）、notes も二重にならない
2. `ステータス：重点` で重点3件 → 作られず保留（受信箱では pending に残る）。重点2件なら重点で作られ `reflect_focus_v1` に出る
3. `■ 実験 新規` に `問い：{実在ID}`・期限 → つながった候補の実験。存在しない問いIDや期限の書式違い → そのブロックだけ読めない、他は適用
4. 題名なし → そのブロックだけ「読めませんでした（題名がありません）」
5. 本文に `紐づけ：` 行 → 新しく作った問い・実験に `links` が付く（実験には `questionId` も）
6. 新規・更新・【振り返り】が混在 → 全部処理、summary に全部。「直前の更新を元に戻す」で新規作成分も消える
7. **実データ相当の再現**：10/27 の `vision-20261027-02` の本文の `■ 問い 新規` 2件 → 2件とも候補で作られ、`■ 実験 R003` の記録は「変更なし」（既に入っている）
8. 既存データは起動だけでは変わらない。375px・コンソールエラー0・構文検証OK・SW版上げ
