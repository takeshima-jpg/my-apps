# Claude Code 修正依頼書：GDrive重複掃除（dedupe）の403ノイズを静かにする

## 背景
JSON.parseエラー（collectAllOSData 710行）は修正済みで、同期・タスク取り込み・brief表示は正常動作している。
残っているのは gdDedupeDrafts（Drive上の重複ファイルのtrash）で出る 403 Forbidden のログのみ。

## 現状
- gdAutoSync → gdDedupeDrafts が、重複ファイルを trash（PATCH）しようとして 403 Forbidden。
- これは**実害なし**：取り込み・保存は先に完了しており、dedupeは個別try/catchで握り潰されるため同期は止まらない。
- ただし毎回同じ複数ファイルで403がコンソールに大量出力され、**本当に見るべきエラーが埋もれる**（ノイズ問題）。
- 403の原因は権限スコープ不足ではなく（GD_SCOPEは /auth/drive で書き込み可）、
  対象ファイルがこのOAuthアプリの所有でない（Google Drive Desktop同期等で作られた）ため trash 不可、と調査済み。

## 修正方針（掃除は「消せるものだけ静かに」）
gdDedupeDrafts（index.html 2269付近）と gdFetch のtrash処理（2189付近）を以下に：

1. **403（および404/権限系）で trash が失敗したファイルは「掃除できない対象」として静かにスキップ**する。
   - console.error / console.warn で大量に吐かない。抑制する。
   - 代わりに、セッション中に一度だけ、まとめて情報レベルで残す程度に留める
     （例：`console.info('dedupe: 掃除できないファイル N件をスキップ（所有外/権限）')` を1行）。
2. **同じファイルへの無駄な再試行を避ける**：一度403になったfileIdを（メモリ内Setで）記録し、
   同一セッションでは再度trashを試みない。永続化は不要（リロードで消えてよい）。
3. dedupeの成否に関わらず、これまで同様に**同期本体は続行**（挙動は変えない・二次防御は維持）。
4. 「同期エラー（再試行）」ボタンの表示条件を確認：**dedupeの403だけの場合はエラー扱いにしない**
   （取り込み・保存が成功していれば同期は成功。dedupeのtrash失敗で"同期エラー"を表示しないようにする）。
   → ユーザーに「同期エラー」と出すのは、取り込み/保存が実際に失敗したときだけにする。

## やらないこと
- スコープ変更・再認証は不要（書き込み権限はある）。
- 所有外ファイルを無理に削除しようとしない（できないものはそのまま残す）。

## 検証
- node --check（pre-commit）
- GDrive同期実行時：403のログがコンソールに大量に出ない（抑制され、多くても情報1行）。
- 取り込み・保存は従来どおり成功し、今日のtasks/briefが反映される。
- dedupeが403だけの状況では「同期エラー（再試行）」ボタンが出ない
  （＝取り込み・保存が成功していれば同期成功扱い）。
- 実際に消せる重複ファイル（所有ファイル）があれば従来どおりtrashされること。
