## §2 構想ログ：種別「戦略目標」（`koso-log/index.html`）
### 2-1 データ
- `item.type` に `'戦略目標'` を足す（既存は `'構想'`｜`'実行'`）。
- ID は構想と同じ **G 番号**（`genId` は `type==='戦略目標'` でも `G` 前置。番号は G の最大＋1）。
- 持つ欄：`id`・`type`・`title`・`purpose`（どんな未来か・任意）・`status`（`検討中`｜`実行中`｜`完了`｜`廃棄`。**PJ化は無い**）・`review`・`createdAt`・`log[]`・`origin`・`relations[]`（構想と同じ）・**`projects[]`＝`[{projectId, projectName}]`（複数）**。
- 画面に出さない欄：`goSign`・`priority`・`trigger`・`prereq`・`success`（ヒックの法則：選ぶものを減らす）。**値が入っていれば消さずに残す**（データは消さない。編集フォームでも隠すだけ）。`parentId` は `'-'`。
- 子の「試し」は持てる（今の G05 に E14 が付いている。11/3 のバックアップで E14 の `parentId` は G05）。
- **`type==='構想'` で判定している所は、戦略目標も「親になれる G」として扱う**。少なくとも次を直す（行番号は 52085ad）：
  - `rebuildParentOpts`（1864付近）：試しの親の選択肢に戦略目標も出す（出さないと E14 を編集・保存したときに親が `'-'` になって外れる）
  - `findG`（1692付近）：戦略目標の G も見つける（`■ 試し 新規 親：G05`・`■ 統合：` が通るように）
  - `applyKosoBlock` の更新の照合（`type===b.type`）：`■ 構想 G05` と書かれた古い形の更新が届いたら、G05 が戦略目標なら**戦略目標として読み**、summary に「G05 は戦略目標です（■ 戦略目標 G05 で書いてください）」と1行（読めませんでした、にはしない）
  - `openRelated`（1234付近）・`buildAllKosoText`（1254付近・壁打ち用の写し）：戦略目標も含める（壁打ちの写しの先頭に「戦略目標」の束）
  - `kiApplyFields` の `isG`（1633付近）：由来・関連は戦略目標にも効かせる
  - `saveItem`：種別が構想でないときにトリガー・前提を空にする処理は、戦略目標では**空にしない**（値を残して画面で隠すだけ）
  - そのほか `type==='構想'`／`type!=='実行'` の判定を grep して、戦略目標をどちらに含めるかを1つずつ決め、報告に一覧で書く

### 2-2 画面
- ホーム（`renderHome` 999〜）：S/A/B/C の束の**上**に「戦略目標」の束を置く。カードは題名・`purpose`（あれば）・つながるプロジェクト名（`projects[].projectName` を `pos_v4` の今の名前に置き換えて「・」区切り）。件数は出さない。
- 一覧（`renderList` 1070〜）：同じく一番上に「戦略目標」の束。詳細グリッドは 2-1 の欄だけ。
- バッジ：`.badge-戦略目標` を1つ足す（色は既存の `.badge-PJ化` と区別がつく落ち着いた色。赤は使わない）。
- 編集フォーム：種別の選択肢に「戦略目標」。選ぶと 2-1 で「持たない欄」が隠れ、「プロジェクト」（`pos_v4` の PJ 名から複数選択・チップで表示）が出る。
- 「PJ化」のボタン・ステータスは戦略目標には出さない。

### 2-3 KOSO-IMPORT
`parseKosoImport`（1571〜）に次を足す。
```
■ 戦略目標 新規
タイトル：スリーエーグループ100年構想
目的：…（任意）
プロジェクト：スリーエーグループ2030構想、チーム竹嶋づくり
ステータス：検討中
記録：気づき｜…
```
- `■ 戦略目標 新規`／`■ 戦略目標 G05`（更新）。`プロジェクト：` は「、」区切りの PJ 名。`pos_v4` で名前一致（`formerNames` も）なら実IDを補い、引けなければ名前だけ残す。`プロジェクト：（空にする）` で空に。**全置換**（書いた分に入れ替え）。
- `■ 廃棄：G05`・`■ 統合：` は戦略目標にも効く。`■ PJ化：` は戦略目標には**効かない**（summary に「戦略目標は PJ化しません」）。
- 退避（`kouso_backup_lastimport`）と「直前の取り込みを元に戻す」は今のまま。
- 紐づけ行の `PJ：` は1つしか持てない（`inboxParseLinks`）ので、戦略目標の PJ は `プロジェクト：` で書く。紐づけ行は今までどおり `links` に入る（人・問い）。
