## 背景（なぜ）

受信箱と REFLECT-IMPORT でできるのは「足す」こと（ログ・問い候補・実験候補・Lectica ログ）だけ。リフレクト見直しで毎回出る**直し**——問いの状態を変える（候補→解消）、実験のつなぎ先（問い）を付け替える、題名の欠けを直す、実験の状態を変える——は取り込みでできず、担当が Chrome で `reflectOS_v1` を直接書いている（本人決定の例外）。直接書き換えは退避・冪等・ログが仕組みで担保されないので、**KOSO-IMPORT と同じ「ID付き更新ブロック」**を REFLECT-IMPORT に足し、直しも受信箱で済むようにする。

## 1. 書式（担当が出す・本人 OK 後に受信箱へ／手貼りも可）

```
【REFLECT-UPDATE】
■ 問い {問いの実ID}
題名：（変更なし）
ステータス：解消
仮説：…
記録：解消の理由｜…

■ 実験 {実験の実ID}
題名：1人に集中して観察する
問い：{つなぎ先の問いの実ID}
ステータス：実験中
場面：…
観察：…
学び：…
記録：気づき｜…

■ 統合：問い {実ID A}, {実ID B} → 新規「{新しい問いの題名}」
理由：…

■ 統合：実験 {実ID A}, {実ID B} → 新規「{新しい実験の題名}」
理由：…
```

- 先頭行 `【REFLECT-UPDATE】`。ブロックは行頭 `■ `。種類は `問い`／`実験`／`統合：問い`／`統合：実験`
- 受け付けるキー（更新のみ・**新規作成はしない**＝新規は従来の REFLECT-IMPORT）
  - 問い：`題名`／`ステータス`（候補・重点・解消・破棄）／`仮説`／`記録`
  - 実験：`題名`／`問い`（つなぎ先の実ID。`（外す）` で `questionId:null`）／`ステータス`（候補・実験中・振り返り待ち・完了・変更・保留・やらない・原則化）／`場面`／`観察`／`期限`（YYYY-MM-DD）／`結果`／`学び`／`記録`
  - 値が空・`（変更なし）` → 触らない。`（空にする）` → 空文字（題名は不可）
  - `記録：種類｜本文` → その問い・実験の `notes[]`（新設・任意）に `{date, kind, text, src:'取り込み'}` を追記。全件に同じ種類＋本文（前後空白除去）があれば入れない（2026-10-26 訂正：当初「直近3件」。claude-code-import-record-dedupe-spec.md が正）。画面は詳細に新しい順・最大3件を薄く（無ければ出さない）
- 統合：KOSO と同じく、**元の問い・実験は `status:'merged'`＋`mergedIntoId`** で残し、新しい方を作る。既存の `tkMergeQModal`／`tkMergeEModal` の保存部分を関数に切り出して呼ぶ（挙動を複製しない）。実験の統合では `questionId` は先頭の実IDのものを引き継ぐ
- 日本語のステータス名は `TK_QST`／`TK_EST` の表示名で照合（英字キーも受ける）

## 2. 上限と入れ替えの扱い（重要）

- `ステータス：重点` で重点が `TK_MAX_FOCUS_Q`（3）に達している、または `ステータス：実験中` で実験中が `TK_MAX_ACTIVE_E`（5）に達しているとき：**勝手に入れ替えない**。そのブロックだけ `ok:false`、理由「重点の問いが3件のため入れ替えが必要です（どれを候補へ戻すか本人が決める）」。受信箱では保留になり、Task OS HOME に理由が出る。手貼りでは status に同じ文言を出す
- `review`（決定検証）は従来どおり数えない

## 3. 取り込みの経路

- `reflectImportText(text, opts)` に `【REFLECT-UPDATE】` の判定を足す（`---REFLECT-IMPORT---` と【振り返り】の判定の前に切り出し、残りは従来どおり）。1つの本文に UPDATE と従来ブロックが混在してよい
- 受信箱（`inboxApply`）も画面の「⬇ 取り込む」も同じ関数を通る。`links` は更新した問い・実験に付ける（既存の `inboxAttachLinks` を流用。`questionId` は実験にだけ）
- **退避**：UPDATE を1件でも適用する直前に `reflectOS_v1` の生文字列を `reflect_backup_lastupdate` に退避（1世代・毎回上書き）。「⬇ 取り込む」画面に KOSO と同じ「直前の更新を元に戻す」リンク（`inbox=1` では出さない）
- 冪等：同じ内容を2回貼っても状態は同じ（`記録` は全件の重複判定）。受信箱の `id` は共通部品が弾く
- 更新・統合・記録追記した問い・実験は `updatedAt` を今日に。探求ボードの表示と `reflect_focus_v1` のミラー（`tkMirrorFocus`）を更新

## 4. 要約（`summary`）
「問い q1 ステータス（候補→解消）／実験 e7 問い付け替え・題名／統合 問い2→新規『…』／記録2件」のように、変わった項目だけ並べる（変わらなかったブロックは「変更なし」）

## 5. 変えないこと
- 従来の REFLECT-IMPORT（【振り返り】→候補の追加）と Lectica 結果ブロックの挙動
- `tkMigrate` の冪等（`sourceCk`）、`reflect_focus_v1` の形式
- 入れ替えモーダル（画面操作のときだけ使う）
- Lectica の実験マスタ（L系）は対象外（Lectica の状態変更は既存のLecticaタブで）

## 6. 受入条件（playwright。単体・`?inbox=1`・手貼りの3経路）
1. 候補の問い q1 に `ステータス：解消`＋`記録：解消の理由｜…` → `status:'resolved'`・`completedAt` 今日・`notes` 1件。同じ本文を再適用 → 変化なし・notes 二重なし
2. 実験 e7 に `問い：q2`・`題名：…` → `questionId` と `title` が変わる。`問い：（外す）` → `questionId:null`。`（変更なし）` は触らない
3. 重点3件の状態で別の問いに `ステータス：重点` → そのブロックだけ `ok:false`・理由に「入れ替えが必要」。他のブロックは適用。受信箱では保留に残る
4. 実験中5件で `ステータス：実験中` → 同じく保留。`review` の実験は数に入らない
5. `■ 統合：問い q1, q2 → 新規「…」` → 新しい問いが候補で1件、q1・q2 が `merged`＋`mergedIntoId`。実験の統合も同様で `questionId` を引き継ぐ
6. 適用直前に `reflect_backup_lastupdate` が作られ、「直前の更新を元に戻す」で戻る（`inbox=1` ではリンクが出ない）
7. UPDATE と【振り返り】が混在した本文 → 両方処理され、summary に両方
8. 存在しない実ID・日本語に無いステータス名 → そのブロックだけ「読めませんでした」、他は適用
9. `reflect_focus_v1` が更新後に再生成される。既存データは起動だけでは変わらない
10. 375px・44px・コンソールエラー0・構文検証OK・SW版上げ

## 7. コミット
「reflect-os: REFLECT-UPDATE（ID付き更新ブロック）を追加。問いの状態・仮説、実験の問い付け替え・題名・状態・場面・観察・期限・学び、記録の追記、統合を取り込みで行えるように（上限超えは入れ替えず保留・退避キーと戻し・冪等）。受信箱と『⬇ 取り込む』の両方で同じ経路。リフレクト見直し担当の Chrome 直接書き換えを不要に」
