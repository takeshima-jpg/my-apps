## 申し送りとの違い（なぜ作り直したか）

申し送りは「【感情記録】の1件に `bodySense` フィールドを足す」前提だったが、現行コードを確認したところ：

- 1day OS に **【感情記録】という専用の欄・データ項目は無い**。記録の項目は `date / satisfaction / events（できごと）/ unease（違和感）/ flags / yumiLoad` だけ
- 【感情記録】は、**できごと欄（`events`）の文章の中の見出し**として書かれている（VISION見直し担当・メンターまとめはこれを原文で読んでいる）
- そのため「1件ごとに `bodySense` を足す」と、1日に複数ある感情行と体の感覚が対応しなくなり、しかもできごと欄の外に別の入力欄が増えて 1day が重くなる

→ **データ構造は変えず、できごと欄の文章の書式で一対にする**。1day 側は、その書式を楽に書くための小さな入力補助だけを足す。

## 決める書式（VISION見直し担当・Morning Brief と共通）

できごと欄の中で、【感情記録】の各行を次の形にする：
```
【感情記録】
・焦り ／ 体：胸の下が詰まる
・ほっとした ／ 体：なし
・嬉しい
```
- `／ 体：〜` が体の感覚。`体：なし`＝思い出せなかった（記録した）。`／ 体：` が無い行＝未入力（「なし」とは区別）
- 区切りは全角スラッシュ「／」、ラベルは「体：」（全角コロン）
- 既存の【感情記録】の行はそのまま（体が無い＝未入力として扱われる）

## 変更内容（入力補助だけ）

### 1. できごと欄の下に小さな補助ボタン列
対象：手動フォーム（`#eventsInput`）と AIX 承認フォーム（`#aix-events-${i}`）の**両方**（9/3 に両フォームを同一構成に統一済み。片方だけにしない）。

- ボタン①「＋感情」：カーソル位置（無ければ末尾）に、できごと欄に【感情記録】見出しが無ければ `\n【感情記録】\n・` を、あれば `\n・` を挿入し、カーソルを「・」の後ろに置く
- ボタン②「体」：カーソルがある行（【感情記録】の下の行）の行末に ` ／ 体：` を足し、カーソルをその後ろに置く。その行に既に `／ 体：` があれば何もしない
- ボタン③「体：なし」：同じく行末に ` ／ 体：なし` を足す（既に `／ 体：` があれば何もしない）
- 候補チップ：過去30日の `events` から `／ 体：〜` の値（「なし」を除く）を出現頻度順に**最大3つ**。押すとボタン②と同じ位置に ` ／ 体：{値}` を足す。過去に1つも無ければ出さない

### 2. 表示
- ログカードの表示は**変えない**（できごと欄はこれまでどおり原文表示。`／ 体：〜` もそのまま見える）

### 3. 画面の方針（UI10法則）
- ヒック：足すのは「＋感情」「体」「体：なし」の3つと候補チップ最大3つだけ
- フィッツ：ボタンはできごと欄の直下・右寄せ、高さ 44px。スマホで親指が届く位置
- ミラー：候補チップは最大3
- ヤコブ：入力はこれまでどおりできごと欄に書く。新しい入力欄・保存の操作を作らない
- ゲシュタルト：補助ボタン列はできごと欄に密着させ、できごと欄の付属物に見えるようにする
- 美的ユーザビリティ：ボタンは本文より小さく・薄い色（既存のフラグチップと同系）

## 変えないこと
- データ構造（`oneday_logs_v1` の項目名・型）。新しいフィールドは**足さない**
- バックアップ（`onedayLogs`）・Morning Brief の読み取り・AIX 下書きの形式（`aix_drafts`）
- 【予測】ブロック（本人判断で取り下げ済み）
- 1day のほかのブロック（行動記録・違和感・フラグ）

## 受入条件（playwright・手動フォームと AIX 承認フォームの両方で）
1. 空のできごと欄で「＋感情」→ `【感情記録】\n・` が入り、カーソルが「・」の後ろ。「焦り」と打って「体」→ `・焦り ／ 体：` になりカーソルが末尾。「胸の下」と打って保存 → `events` に `・焦り ／ 体：胸の下` が入る
2. 2行目で「＋感情」→ 見出しは増えず `・` だけ増える。「ほっとした」と打って「体：なし」→ `・ほっとした ／ 体：なし`
3. 既に `／ 体：` がある行で「体」「体：なし」を押しても二重にならない
4. 過去30日の記録に `体：胸の下` が2回・`体：肩` が1回あれば、候補チップが「胸の下」「肩」の順に出る。「なし」はチップにならない。0件ならチップ列が出ない
5. 既存の日の記録を開いても中身・表示が変わらない（体の無い行に「なし」が付かない）
6. AIX 承認フォームでも 1〜4 が同じように動き、承認で保存した `events` に反映される
7. `oneday_logs_v1` のキー構成が改修前後で同じ（新しいキーが無い）
8. 375px 幅で崩れない・ボタン 44px・コンソールエラー 0・構文チェック OK
