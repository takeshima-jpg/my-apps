## 背景（なぜ）

11/1 のリフレクト棚卸しで本人と決めたこと：
- Reflect の問い・実験＝「自分がどう在るか・どう関わるか」（PJが変わっても持ち越す）。Project の問い・実験＝「その案件をどう進めるか」
- つながり：VISION → テーマ（在り方の軸）→ 問い → 実験 → Lectica（PJの場面で試す）
- 完了した実験58本に学びが1本も残っていない

ところが Reflect OS は、Project OS のPJを毎回テーマとして写している（`syncFromProjectOS`：起動時・`pos_v4` の変更時・「↺ PJ同期」ボタン。id `pos_{PJ id}`、状態はPJの状態で毎回上書き）。テーマ14本のうち6本が写し。取り込みで外しても次に開くと作り直される。
本人決定（11/2・A）：**写すのをやめる。今ある写しのテーマは「外した」印を付けて残し、新しいPJもテーマにしない。外したテーマに付いていた問い・実験は、PJとのつながり（links の projectId）が残るようにする。**

## 1. PJのテーマ写しをやめる

- `syncFromProjectOS` を呼ばない（起動時 3621行付近・`posLiveSync` 3319行付近・「↺ PJ同期」ボタン 932行付近）。ボタンと「プロジェクト」節の同期UIは外す（関数は残してよいが呼ばれない）
- テーマ詳細でPJ由来の参照表示（goal／centerPin／badFuture／successConditions／nextMove）を出している箇所は、外したテーマでは出さなくてよい（データは消さない）
- **起動時1回・冪等の移行**（実行前に `reflectOS_v1` を `reflect_backup_detach_20261102` へ退避。同名キーがあれば作らない。フラグ `reflect_detach_20261102_done`）：
  1. id が `pos_` で始まるテーマ全部に `detached:true`・`detachedAt`（今日）・`projectId`（`pos_` を除いた部分）を付ける。`status` などほかは変えない（`_fromProjectOS` の有無を問わない）
  2. 問い・実験のうち `themeIds` にそのテーマを含むものは、`links` が無い／`links.projectId` が無ければ `links.projectId`＝そのPJの id、`links.projectName`＝テーマの title を足す（既にある `links` のほかの項目は変えない）。`themeIds` からは外さない（つながりの履歴として残す）
  3. 移行後、トーストを1回「PJのテーマ n本を外しました（問い・実験のPJとのつながりは残しています）」
- 外したテーマ（`detached:true`）は、テーマ一覧・ログのテーマ選択・問いのテーマ選択・ホームの表示から外す。テーマ一覧の末尾に折りたたみ「外したテーマ」（開くと一覧・「戻す」で `detached:false`）
- バックアップの `reflectOS` 要約（themes）にも `detached` を出す（Morning Brief などが読むため）

## 2. REFLECT-UPDATE に「■ テーマ」

```
【REFLECT-UPDATE】
■ テーマ {テーマの実ID}
題名：…
状態：実行中
問い：…（＝現在の状態。画面で「問い」と出ている欄）
仮説：…
記録：…
紐づけ：…
```

- 見出し `■ テーマ {実ID}`（更新のみ）と `■ テーマ 新規`（題名必須・状態省略＝構想中）
- キー：`題名`→`title`／`状態`→`status`（構想中・実行中・保留・完了・撤退。**`外した`** は `detached:true`、`戻す` は `detached:false`）／`問い`・`現在の状態`→`currentState`（同じ欄）／`仮説`→`summary`／`記録`→`notes[]`（既存の `rfPushNote`。全件で重複判定）
- `（変更なし）`／`（空にする）` は既存の問い・実験と同じ扱い
- 完了にしたら `completedAt`、完了以外へ戻したら外す（画面の挙動 812・823行に合わせる）
- 紐づけ行：その取り込みで作った・直したテーマに `links` を付ける（既存の `inboxAttachLinks` に themes を足す）
- 冪等：同じ本文を2回で状態は同じ。退避（`reflect_backup_lastupdate`）と「直前の更新を元に戻す」の対象
- summary：「テーマ th_01 状態（実行中→完了）」「テーマ 新規『…』」「テーマ pos_xxx 外した」

## 3. REFLECT-UPDATE に「■ 原則 新規」

```
■ 原則 新規
題名：…
分類：対話
説明：…
元の実験：{実ID}, {実ID}
元の問い：{実ID}
```

- 画面の「原則を追加」（`tkPrincipleForm` の保存・2590行）と同じ形で作る：`{id, title, category, description, sourceExperimentIds, sourceQuestionIds, status:'active', createdAt, updatedAt}`。保存部分を関数に切り出して両方から呼ぶ（複製しない）
- `分類`：対話・判断・組織・自分・その他（`TK_PCAT` の表示名。英字キーも可）。省略＝その他
- `元の実験`／`元の問い`：実ID（実験は R番号も可）。存在しないIDは読めない（そのブロックだけ）
- 題名必須。同じ題名の原則（archived 以外）が既にあれば作らず「既にあります」
- 元の実験を `principled`（原則化）にはしない（状態の変更は `■ 実験 {ID}` の `ステータス：原則化` で別に）
- summary：「原則 新規『…』（対話・元の実験2）」

## 4. 実験を完了にするとき「学び」1行を必須に

- 対象：`status` を `complete`（完了）にするすべての経路
  - 探求ボードのカードの「完了」（`tkSetEStatus`）、一括操作の「完了」（`tkBulkE`）、実験の記録フォームの状態「完了」（2468行付近）
  - REFLECT-UPDATE の `ステータス：完了`
- 画面：`learning` が空なら、完了の前に1行の入力を出す（その場で開く小さな欄。モーダルなら簡素に）。「学びなし」のボタンもあり、押すと `learning:'（学びなし）'` で完了。空のまま完了はできない
- 一括完了：学びが空のものは完了にせず残し、トースト「学びが空の実験 n本は残しました（1本ずつ完了できます）」
- REFLECT-UPDATE：`ステータス：完了` のブロックで、そのブロックの `学び：` も既存の `learning` も空なら、**そのブロックだけ**「読めませんでした：学びがありません（学び：なし と書けば完了できます）」。`学び：なし` は `learning:'（学びなし）'` として完了
- 既に完了している実験（58本）はさかのぼって変えない
- Lectica の実験マスタ（L系）は対象外

## 5. REFLECT-UPDATE の「■ 問い 新規」に「テーマ」キー

- `テーマ：{テーマの実ID}`（または題名の完全一致）→ `themeIds:[id]`。`テーマ：なし` → `themeIds:[]` と `noTheme:true`
- 省略しても作れる（今は必須にしない。担当の書式を揃えてから必須にするかを決める）
- 外したテーマのIDを指定したら「読めませんでした：外したテーマです」

## 6. 受入条件（playwright。単体・`?inbox=1`・手貼り）

1. 起動で `pos_` テーマ6本が `detached:true`、問い・実験の `links.projectId` が補われる。退避キー1つ、再読み込みで二度走らない。Project OS で保存しても `pos_` テーマが作られない・状態が変わらない。新しいPJを作ってもテーマができない
2. 外したテーマは一覧・選択肢に出ず、「外したテーマ」の折りたたみに出る。「戻す」で一覧に戻る（戻しても同期はされない）
3. `■ テーマ th_01` で状態・題名・問い・仮説・記録が変わる。`状態：外した` で外れる。`■ テーマ 新規` で1本できる。再適用で変化なし
4. `■ 原則 新規` で原則ができ、画面の原則一覧に出る。同じ題名の2回目は「既にあります」。存在しない元の実験IDはそのブロックだけ読めない
5. 画面の「完了」で学びが空なら入力が出て、空では完了できない。「学びなし」で完了。一括完了で学び空は残りトースト1回
6. REFLECT-UPDATE `ステータス：完了` で学び空 → そのブロックだけ読めない。`学び：なし` で完了・`（学びなし）`
7. `■ 問い 新規` の `テーマ：` が `themeIds` に入る。`テーマ：なし` で空＋`noTheme`
8. 「直前の更新を元に戻す」でテーマ・原則の変更も戻る
9. 構文検証OK・コンソールエラー0・375px・SW版上げ
