# Claude Code 実装依頼書：Reflect OS「意思決定検証」を左メニューに独立させる

> ✅ 実装済み 2026-07-19 ・ `2da4c91`
> 実装メモ：分離は tkIsReview() による表示フィルタで実現（データ移動なし＝既存 review 実験が
> そのまま新メニューに現れる）。3枠別管理は tkActiveEs() を explore 限定にし、
> tkSetEStatus の制限判定から review を除外。【意思決定ログ】のマップは
> 決定→title／理由・背景・判断軸→scene／成功条件・成否の見方→observation／検証日→deadline／
> 原則・メモ→note（原則は自動で実践原則化せず note に保持＝原則化は既存フローで竹嶋が判断）。

作成日：2026-07-19
対象：repoの `reflect-os/index.html`。作業前に `git pull`。
※ 決定検証（expType='review'）は既に探求ボード内に実装済み。本依頼はデータ構造の新設ではなく
  「動線・表示の格上げ」——実験箱から取り出して独立メニュー化する。既存データは流用・破壊しない。

## 背景と役割
決定検証の運用が確定した：
- 検証の"壁打ち"は claude.aiの専用プロジェクトで行う（Claudeが決定理由の確認・検証日設定・
  検証日の振り返り評価を支える）。
- その出力を Reflect OS「⬇取り込む」から取り込む（既存のREFLECT-IMPORT/【意思決定ログ】経路）。
- **Reflect OSの役割は、決定と検証結果を保管・一覧する器**。
現状これが探求ボード＞候補＞実験追加＞🔍決定検証、と3階層奥にあり、かつ問い・実験とは
別軸なのに実験箱に同居している。これを左メニューの独立項目に出す。

## 変更1：左メニューに「意思決定検証」を追加
- 左メニュー並び：ホーム / ログ / 探求ボード / **意思決定検証** / Lectica / 検索 / アーカイブ /
  VISION設定 / 取り込む（探求ボードの直下が自然）。
- アイコンは 🔍 か ⚖️（既存の決定検証表示に合わせる）。

## 変更2：意思決定検証ページ（保管・一覧の器）
expType='review' の実験を、探求ボードから分離してこのページに一覧する。
- **一覧表示**：決定内容／検証日（deadline）／状態（検証待ち/検証済み等）／成否の見方（observation）／
  検証結果（振り返り済みなら learning）。検証日の近い順、または 検証待ち→検証済み の区分表示。
- **検証日が近い（14日以内）ものを上部に**「あとN日」で示す（事実表示・催促トーンにしない）。
- **状態区分**：検証待ち（active・検証日前）／要検証（検証日到来）／検証済み（振り返り済み＝learningあり）。
- 各項目から既存の「振り返る」を呼べる（検証結果の記録＝learning化。既存フロー流用）。
- 手動追加ボタン（＋決定検証）も置く（claude.ai経由でなく直接記録したいとき用・既存の
  検証用フォーム＝決定/検証日/成否の見方 を流用）。

## 変更3：探求ボードから決定検証を外す
- 探求ボード（重点/候補/実践原則/完了）には expType='review' を**表示しない**
  （問い・実験の純粋な探求サイクルに戻す）。「＋実験を追加」内の決定検証トグルは撤去してよい
  （決定検証の追加は新メニュー側に集約）。ただし既存データは消さず、新メニューに移すだけ。
- 探求ボードの実験中3枠は expType='explore' のみで数える（決定検証は別カウント＝独立枠に）。
  ※前回「3枠共有」としたが、独立メニュー化に伴い**決定検証は探求の3枠と別管理**に変更する。

## 変更4：取り込みの振り分け
- 「⬇取り込む」で【意思決定ログ】/検証系ブロックを取り込んだとき、expType='review' として
  意思決定検証ページに入る（探求ボードの候補には出さない）。
- 通常の【振り返り】/REFLECT-IMPORT（問い・実験）は従来どおり探求ボードへ。
- 判別はブロック種別（【意思決定ログ】等）で行う。パーサが未対応なら、
  【意思決定ログ】ブロックの取り込みに対応させる（決定/理由/成功条件/原則/検証日 を
  expTypeレビュー実験の各フィールドへマップ・報告に明記）。
