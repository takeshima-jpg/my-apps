## §1 経緯
- 本人の決定（11/24）：「一日ひとつは信頼、愛情を誰かに与える活動をしていこうと思う」「1dayOS上でやりたい」。Reflect OS には実験「一日ひとつ、誰かに信頼・愛情を与える」が置かれている。**毎日の記録は 1day OS だけに書く**（毎回の Lectica 記録は求めない）
- リフレクト見直し担当からのお願い：1day に毎日の記録欄を1つ足す。ワンタップと一言メモ。**押さなかった日が評価に見えない形**（催促や未達の表示は出さない）
- 1day には、近い形の欄「🏠 今日、ゆみさんの負荷を一つ引き取ったか」（`yumiLoad: 'yes'|'no'`・`yumiLoadNote`）がある。入力は「＋記録する」の画面（459 付近）と AIX 承認フォーム（2081 付近）、表示はログのカード（1403 付近）、集計は上のカード（`renderYumiSummary`・「いいえ」の連続と ⚠ を出す）
- 今回の欄は、**「いいえ」を作らない・集計を出さない**形にする（「いいえ」の記録や連続の数字は、押さなかった日の評価になるため）

## §2 データ（`oneday_logs_v1` のログ1件に足す項目）
- `gave: true` … 与えた日だけ持つ。押していない日は**項目そのものを持たない**（`false` を書かない）
- `gaveNote: '…'` … 一言メモ（誰に・何を）。空なら項目を持たない。`gave` が無いときは `gaveNote` も持たない
- 今あるログは書き換えない（項目が無い＝押していない、で読む）。バックアップ（`onedayLogs`）にはそのまま入る

## §3 入力
### 3-1 「＋記録する」の画面（新規・編集とも）
- 「🏠 今日、ゆみさんの負荷を一つ引き取ったか」の欄の**すぐ下**に、欄を1つ足す
  - ラベル：**「🤲 今日、誰かに信頼・愛情を与えた」**
  - ボタンは**1つだけ**：**「与えた」**（ゆみさんの欄の「はい」と同じ大きさ・同じ選んだときの色。横幅は欄いっぱい）。押すと選ばれ、もう一度押すと外れる。「いいえ」のボタンは作らない
  - 選ばれているときだけ、下に一言メモの入力欄を出す：placeholder **「誰に・何を（任意・1行）」**
- 保存（`saveEntry`）：選ばれていれば `gave: true` と（あれば）`gaveNote`。選ばれていなければ両方の項目を消す（編集で外したとき）
- 編集で開いたとき：`gave` があれば選ばれた状態・メモ入り。新規で開いたときは選ばれていない・メモ空
- 必須にしない。押さずに保存しても何も出さない

### 3-2 AIX 承認フォーム（大きい形のカード・`renderAixDraftList`）
- 同じ欄を、ゆみさんの欄のすぐ下に足す（ボタン「与えた」1つ・選ばれているときだけ一言メモ）
- 「保存」（`aixApproveByIdx`）：
  - 新しいログになるとき：選ばれていれば `gave: true` と（あれば）`gaveNote`
  - その日のログがすでにあるとき（今ある分岐）：選ばれていれば `gave: true`、メモがあれば `gaveNote` を入れる。選ばれていなければ**何も変えない**（前の `gave` を消さない）
- **「保存済みの日に足す」の小さいカード（`append: true`）には足さない**（足すのは「できごと」だけ・今のまま）
- あわせて直す：`renderAixDraftList` の最後で `_aixSat_i`・`_aixFlags_i` を空に戻している所で、**`_aixYumi_i` と、今回足す選択の変数も空に戻す**（今は `_aixYumi_i` が描き直しで戻らず、前のカードで選んだ「はい／いいえ」が画面に出ていないまま残る）

## §4 表示
- ログのカード：`gave` があるログに、ゆみさんの行（`log-yumi`）のすぐ下に1行 **「🤲 与えた：{メモ}」**（メモが無ければ「🤲 与えた」）。色はゆみさんの「引き取った」と同じ（`var(--sat-great)`）
- `gave` が無いログには**何も出さない**（「未記録」「—」「与えていない」などを出さない）
- **集計・連続日数・達成率・カレンダー・バッジ・知らせは作らない**。上のゆみさんのカード（`renderYumiSummary`）にも足さない
- 検索・絞り込み・印刷・書き出しがログの本文を出している所は、今のまま（この欄を足さなくてよい）

## §5 触らないもの
- ゆみさんの欄（`yumiLoad`）の動き・集計・⚠
- 今あるログの中身、できごとの本文（本人が欄ができるまでの間に書く「【与えた】誰に・何を」の行は、そのまま残す。欄へ自動で移さない）
- 受信箱の下書き（`targetOS: oneday`）・`daily-tasks.json` の下書きの書式（この欄は下書きに持たせない＝いつも空で出る）
- Task OS・Reflect OS・バックアップの作り
- スマホ幅の確認は不要（PC だけ）

設計の根拠（UI心理学）：ヒックの法則（ボタンは「与えた」1つ。「いいえ」を選ばせない）／ヤコブの法則・ゲシュタルトの法則（ゆみさんの欄のすぐ下に、同じ見た目で置く）／フィッツの法則（欄いっぱいの大きいボタン）／フォン・レストルフ効果（与えた日だけログに1行出る）／ツァイガルニク効果を**使わない**（未完了・連続・達成率を見せない。押さなかった日が評価に見えないように、という本人側の決め）／損失回避（今あるログを書き換えない・承認フォームで押さなかったときに前の記録を消さない）

## §6 確かめること・報告の形
確かめること（Code 自身の確認・試しのデータで）：
1. 「＋記録する」で「与えた」を押してメモを書いて保存 → ログに `gave: true`・`gaveNote` が入り、カードに「🤲 与えた：{メモ}」が出る
2. 「与えた」を押さずに保存 → ログに `gave`・`gaveNote` の項目が無く、カードに何も出ない。画面のどこにも「未記録」「0」などが出ない
3. 1 のログを編集で開く → 選ばれた状態・メモ入り。外して保存 → 両方の項目が消える。メモだけ消して保存 → `gave: true` だけ残る
4. AIX 承認フォーム（大きい形）で「与えた」を押して保存 → 新しいログに入る。その日のログがすでにあって `gave: true` のとき、押さずに保存しても `gave` が消えない
5. 「保存済みの日に足す」の小さいカードに、この欄が出ない
6. 承認フォームで1枚目のカードの「はい」と「与えた」を押してから、そのカードを「スキップ」→ 描き直された次のカードを、何も押さずに「保存」→ そのログに `yumiLoad`・`gave` が入っていない
7. ゆみさんの欄と上のカードの集計が、直す前と同じ
8. 今あるログ（項目の無いログ）が保存・編集の前後で書き換わっていない。PC 幅（1280px）で崩れない
