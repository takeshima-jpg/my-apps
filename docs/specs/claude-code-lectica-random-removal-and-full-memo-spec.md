## 竹嶋さんの決定（2026-08-20・実機で3回連続の不整合を確認した上での判断）
1. **ランダム生成は完全廃止**。提案が無い日はLecticaを出さない（空でよい・催促しない）
2. Task OS/Shot OSに、Briefの✦枠と同じ内容（重点の問い・実験・使う場面・完了条件・今日振り返るなら）が**開かずに読める**状態で表示されるようにする
3. Shotの完了✔は**確認ダイアログを挟む**（開くボタンの隣で誤爆するため）

## 今日の実機で起きた不具合（原因の記録）
- 同期のたびに新しいランダムが生成され、3回連続で別のランダムが座った
- 竹嶋さんがランダムを完了(done)にすると、当日Lecticaが`done`で残り、`autoGenLecticaShot`が
  `curIdx>=0 → return 0` で置き換えも新規追加もしなくなる一方、別経路でランダムがさらに生成される
- BriefはR002（Reflect実験・マスタ外ID）を出しているが、`byId(pid)`→`usable`で落ちて採用されない

## 修正内容

### ① ランダム生成を完全廃止する
`autoGenLecticaShot()` から**ランダム分岐（②のブロック・14日連続回避・poolからのrandom選定）を全て削除**する。
- `allowRandom` 引数は撤去（全呼び出しから引数を外す）
- 提案（当日の有効な `aix_lectica_pending`）が無い場合は**常に return 0**（何も生成しない）
- 呼び出し3箇所（AIタスク読込・GDrive同期C3・DOMContentLoaded）は、そのまま `autoGenLecticaShot()` を
  引数なしで呼ぶ形に統一
- `lecticaSource` の 'random' は今後書かれなくなるが、既存データに残る 'random' を差し替え対象と
  みなす判定（isRandom）は**残す**（移行期の掃除のため）

### ② R系（Lecticaマスタ外ID）の提案を受け入れる
提案IDがマスタに無い場合も採用する。
- `sanboExp` が取れない（byId→null）でも、`pending` の日付一致かつ `shotTask`（またはタイトル）があれば
  **提案を信頼して採用**する
- Shot生成・置き換えに使うタイトル/カテゴリ/メモは `pending.shotTask` を正とする
- memoの実験ID行は `pending.selectedExperimentId` をそのまま書く（例：`実験ID：R002`）
- マスタ更新（not_started→active昇格）はマスタに無いIDでは**スキップ**（エラーにしない）

### ③ 完了済み(done)の当日Lecticaがあっても、新しい提案は反映する
現状は当日Lecticaが1件でもあると `return 0`。これを次のように変える。
- 当日のLecticaが **todo/doing** かつ **random由来** → 提案で**置き換え**（現状維持）
- 当日のLecticaが **done/pending/rejected**（実行済み等）→ その古いShotは**そのまま残しつつ**、
  **提案の実験IDが既存と異なる場合は、提案を新規Shotとして追加する**
  （＝実行済みの古いものは履歴として残し、今日の提案は別途表示される）
  - ただし提案の実験IDが、当日の done Shot と**同一ID**なら追加しない（二重防止）
- 当日のLecticaが無い → 提案を新規追加（現状維持）

※この結果、竹嶋さんが誤って完了にしても、次の同期で正しい提案がもう一度出てくる。

### ④ Shotに実験内容をフル表示する（開かずに読める）
現状 `pending.shotTask.memo` に使う場面等が入るが、Shot一覧のカードは**タイトルしか見せていない**。
- `pending.shotTask` に、Briefの✦枠と同じ構造化データを持たせる前提で（Cowork側FB追補Gで対応）、
  Shot OSのLecticaカードは、memoに含まれる以下を**カード上に展開表示**する：
  重点の問い／実験／使う場面／完了条件／今日振り返るなら
- 表示は「開く」を押さなくても見える形（カード内に折りたたみ無しか、既定展開）
- memoにこれらが無い旧Shotは従来どおりタイトルのみでよい（後方互換）

### ⑤ ✔完了ボタンに確認ダイアログ
Shot OSのLecticaカード（少なくともLecticaカテゴリ）の完了✔押下時に、
`confirm('この実験を完了にしますか？')` 相当を挟む。OKで完了、キャンセルで何もしない。
- 「開く」ボタンとの距離も可能なら少し離す（副次対応・必須ではない）
- Lectica以外のShotにも同じ確認を付けるかは実装judge（竹嶋さんの誤爆はLecticaで発生）

## 変更しないこと【厳守】
- 提案による差し替えの冪等性（同じ提案の再取り込みで変化しない）
- 手動追加Shot・sanbo由来Shotを上書きしない
- reflect_focus_v1 の重点カード表示（HOMEの◇重点の問い）には触れない
- 自動pause（lecticaAutoPaused）ロジック

## 検証
- 構文検証（node --check）
- 提案あり（L系）→ Shot 1件・内容フル表示
- 提案あり（R系・マスタ外）→ Shot 1件・memoに実験ID：R002・内容フル表示
- 提案なし → Lecticaが生成されない・空・エラーなし・警告文も出ない

- 当日doneあり（同一ID）＋提案 → 追加されない
- 同期を複数回 → ランダムが一切生成されない（3連発の再発なし）
- ✔押下 → 確認ダイアログが出る・キャンセルで完了しない
- Shotカードに重点の問い〜今日振り返るならが開かず読める
- リロード後維持・コンソールエラーなし
