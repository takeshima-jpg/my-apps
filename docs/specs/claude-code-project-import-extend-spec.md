## 1. 受け付けるラベル（追加分）

既存（PJ／決定／学び／分岐／次の一手／問い／ゴール／注意論点／成功条件／悪い未来／センターピン／答え合わせ／予測）はそのまま。次を足す。

| ラベル | 書き方 | 動き |
|---|---|---|
| `名称:` | 新しい名前 | `p.name` を置換。旧名は `p.formerNames[]` に追加（重複なし）。ムーブ「見立て更新」に「名称変更：『旧』→『新』」 |
| `ステータス:` | 構想中／進行中／停滞／完了／保留 | `p.status` を置換。ほかの語は読めない（下の §5）。ムーブ「見立て更新」に「ステータス：旧→新」 |
| `期限:` | `YYYY-MM-DD`／`（空にする）` | `p.deadline` を置換。ムーブ「見立て更新」に記録 |
| `フェーズ:` | `１ テーマ（目標）／２ テーマ／…` | §2 |
| `制約:` | `YYYY-MM-DD タイトル（状態）／…。削除：YYYY-MM-DD タイトル／…` | §3 |
| `分岐:` | 従来の1件（`… @YYYY-MM-DD`）に加えて、`YYYY-MM-DD タイトル／…。削除：…` の複数件 | §3 |
| `新規:` | `する` | §4 |

- ラベルの表記ゆれ：`名前`＝名称、`状態`＝ステータス、`締切`＝期限、`重点テーマ`＝フェーズ（`phaseLabel` が theme のPJ向けの呼び方）も受ける
- 同じラベルが複数行ある場合：名称・ステータス・期限・フェーズは**最後の1行**、分岐・制約は**全行を順に**処理

## 2. フェーズ（全部置き換え）

- 「／」で区切り、各片の先頭の番号（全角・半角の数字。`１`／`1`／`①` も可）を `phase`、残りを `theme`。末尾の `（…）` が1つあればそれを `goal`、無ければ `goal:''`。`phase` は既存データに合わせて**全角数字**で保存
- 番号で始まらない片（例「旧１『2030勝ち筋と変化理由の定義』は完了」）は使わず、summary に「フェーズの読まなかった部分：…」
- 1件以上読めたら `p.phases` を丸ごと置き換え。置き換える前の `p.phases` は、ムーブ「見立て更新」に「フェーズ置き換え：旧 n件→新 m件」として残し、旧配列はそのムーブの `prev` に JSON で持つ（削除しない原則）
- 既存の分岐・制約の `phase` は書き換えない（番号がずれても表示は今と同じ扱い）
- 同じ内容なら何もしない（冪等）

## 3. 分岐・制約（複数件・更新・削除）

本文を `削除：`（全角コロン・半角も可）で前後に分ける。前＝足す／直す、後＝削除。どちらも「／」で区切り、各片の末尾の「。」と前後の空白を除く。

**足す／直す（各片）**
- 片の先頭が `YYYY-MM-DD` ならそれを日付、残りをタイトル。分岐は末尾 `@YYYY-MM-DD` の従来形も受ける
- 制約だけ：末尾の `（未着手）`／`（着手）`／`（進行中）`／`（保留）`／`（完了）` を状態に（`着手`＝`進行中`）。無ければ新規は `未着手`、既存は変えない。日付の無い片も可（`date:''`）
- 照合：同じ日付の既存が**1件**ならそれを直す（タイトル・状態を置換）。同じ日付が複数なら、タイトルが部分一致（前後どちらの包含でも・空白と全角半角をそろえて）するものを直す。日付が無い片はタイトルの部分一致で照合。合うものが無ければ足す
- 分岐の新規：既存と同じ形 `{id:uid(), date, status:(date>today?'future':'past'), title, what:'', why:'', nextAction:'', stakeholders:''}`。日付が無い分岐の片は**足さずに** summary へ「日付の無い分岐は足していません：…」
- 制約の新規：既存の形 `{id:uid(), date, status, phase:'', sentiment:'', _category:'constraints', title, content:'', goal:'', stakeholders:'', updatedAt}`
- 片が1つで「／」も日付も無い従来の書き方（`分岐: 文 @YYYY-MM-DD`／`分岐: 文`）は**今までどおり**（ムーブ＋分岐1件）

**削除（各片）**
- 片の先頭の `旧` は取り除く。日付があれば、同じ日付の既存が1件ならそれ、複数ならタイトルの部分一致。日付が無ければタイトルの部分一致（1件に絞れたときだけ）
- 消す前の要素は、ムーブ「見立て更新」に「分岐削除：YYYY-MM-DD タイトル」（制約は「制約削除：…」）として残し、要素そのものをそのムーブの `prev` に持つ。配列からは取り除く
- 見つからない／複数に当たって絞れない片は消さず、summary に「削除できませんでした：…（見つかりません／複数あります）」

**ムーブ**
- 複数件の分岐・制約の行は、ムーブを1件にまとめる（kind は「見立て更新」、本文「分岐：足す n・直す n・削除 n」）。分岐1件ごとのムーブは作らない（タイムラインが埋まるため）

## 4. PJ新規（`新規: する`）

- `PJ:` の名前に合うPJ（`piCands`。§6 の旧名も含む）が**無いとき**だけ、新しいPJを作る。形は画面の「新規プロジェクト」と同じ（`openProjModal` の保存部分を関数に切り出して使う。複製しない）。`status` は `ステータス:` があればそれ、無ければ `構想中`。`priority` は `中`
- その後、同じ本文の残りのラベル（ゴール・センターピン・分岐…）を通常どおり適用する
- 合うPJが**あるとき**は作らず、既存に適用（2回貼っても2つできない）。summary に「新規：既にあります（名前）」
- `新規:` が無く、合うPJも無い場合は今までどおり「該当するPJが見つかりません」（打ち間違いでPJが増えないように）
- 受信箱：`links.projectId` があればそれが最優先（今までどおり）。`新規: する` で作ったPJの実IDは summary に「新規 {実ID}」と出す（担当が翌朝の紐づけ行に使う）

## 5. 読み飛ばしの報告（重要）

- ラベル行（`ラベル: 値` の形）なのに上のどれでもない行は、黙って捨てずに summary の末尾に「読まなかった項目：期限, 担い手」のように**ラベル名だけ**並べる
- `ステータス:` の語が読めない、`期限:` の書式が違う、なども「読めませんでした：ステータス（〇〇）」で summary へ。ほかの項目は適用する
- 受信箱の「済み／保留」の判定は変えない（1件でも入れば済み）。担当は翌朝の `importInbox.log` の summary で確かめる
