# Claude Code 実装依頼書：1day ログのタグ/フラグをスリム化

## 背景

1dayのタグ・フラグが多すぎて使われていない。実運用に合わせて整理する。

- タグ8種のフィルタは一度も使っていない／ブログはもう書いていない／VISION振り返りはReflectの役割。  
- 満足度評価と違和感・エネルギーが二重になっている。

## 変更対象

1day/index.html のみ。**既存ログデータは壊さない**（撤去する項目の値がデータに残っていても表示・保存でエラーにしない）。

## 1\. 撤去するもの

- **タグ8種**（経営/組織/人間関係/家族/健康/感情/学び/未来）：記録時のタグ付けUI、および モバイルナビ・サイドバーのタグフィルタ（tag:～）ボタンをすべて撤去。  
- **ブログ候補フラグ**（blog）：入力ボタン・フィルタ（flag:blog）を撤去。  
- **VISION関連フラグ**（vision）：入力ボタン・フィルタ（flag:vision）を撤去。

## 2\. 満足度評価を4段階に

- 現在の ◎ 〇 △（sat-btn）に **× を追加**して ◎ 〇 △ × の4段階にする。 意味の目安をラベルかtooltipで：◎良い/充実 〇普通 △もやもや ×悪い。  
- 「エネルギー高」の感覚はこの満足度◎に吸収（エネルギー高フラグは撤去・下記3）。

## 3\. フラグの整理（違和感は独立で残す）

- **違和感フラグ（unease）は残す**：満足度とは別軸の「引っかかった・後で見返す」マークとして維持。 入力ボタンとフィルタ（flag:unease）も残す。  
- **エネルギー高フラグ（energy）は撤去**：満足度◎に吸収（入力ボタン・フィルタ flag:energy を撤去）。  
- **深掘りフラグ（deep）は残す**：入力ボタン・フィルタ（flag:deep）を維持。  
- 結果、残るフラグは「△違和感」「◎深掘り」の2つ。フィルタも「すべて/違和感/深掘り」に集約。

## 4\. データ保護

- 既存ログに tags 配列・blog/vision/energy フラグの値が残っていても、表示・編集・保存・ GDrive/JSONバックアップでエラーにしない（単に無視して表示しない・保存時も既存値は破棄してよいが 破棄でクラッシュしないこと）。  
- Coworkの1day下書き取り込み（aix\_drafts）や brief表示への影響が無いこと。

## 検証

- node \--check（pre-commit）  
- 記録画面：満足度◎〇△×が選べる／違和感・深掘りフラグが残り、タグ・ブログ・VISION・エネルギー高が消えている  
- フィルタが「すべて/違和感/深掘り」に集約され、タグフィルタが消えている  
- 旧タグ/旧フラグ付きの既存ログを開いてもエラーにならない（表示・編集・保存OK）  
- モバイル幅でナビが崩れない
