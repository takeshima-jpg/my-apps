## 背景（なぜ）

11/1〜11/3 のリフレクト棚卸しで、テーマ・問い・実験のつながりを整理し直した（テーマ＝在り方の軸、テーマが探る問いは「重点の問い」だけで表す）。テーマの「問い」欄（`currentState`）と重点の問いが同じ文の2重になっている。PJ向けの欄（関連PJ・マイルストーン・指標）と、10/19 から使っていない実験の欄（実践回数・最後の実践日）も残っている。

## 1. テーマの「問い」欄（`currentState`）をなくす

- テーマの入力欄・詳細・カードから「問い」（`currentState`）を外す
- テーマのカードと詳細に、**そのテーマの重点の問い**（`status:'focus'` かつ `themeIds` にそのテーマ）を自動で並べる。無ければ薄く「重点なし」
- **起動時1回の移行**（退避 `reflect_backup_board_20261103`・フラグ `reflect_board_20261103_done`）：`currentState` が空でないテーマは、その文を `notes[]` に `{date: 今日, kind:'記録', text:'（旧「問い」欄）' + 本文, src:'整理'}` として足し、`currentState` を消す（外したテーマ・完了のテーマも同じ。今は15本中14本に文がある）
- REFLECT-UPDATE の `■ テーマ` から `問い：`／`現在の状態：` キーを外す（書かれたらそのブロックだけ「読めませんでした：テーマの問い欄はなくなりました（重点の問いで表します）」）
- Task OS のバックアップ要約（`readReflectOSFromIDB`・790行付近）の `themes[].question` は、`currentState` の代わりに**そのテーマの重点の問いの題名**を「／」でつないだ文にする（キー名は互換のため残す）

## 2. 実験中の上限を「重点の問い1本につき5本」に

- `TK_MAX_ACTIVE_E`（全体5）を、**重点の問いごとに5本**の判定に置き換える（決定検証 `expType:'review'` は今までどおり数えない）
- **重点でない問い・問いにつながっていない実験は、新しく実験中にできない**（本人決定の案どおり）。画面・一括・REFLECT-UPDATE・統合の引き継ぎ・下書きの選択、どこでも。理由は「重点の問いにつないでから実験中にできます」
  - 画面の「実験中にする」：つながる問いが重点でなければ、その場で重点の問いを選ぶ欄を出す
- 既に実験中で、重点でない問いにつながっている・つながっていない実験はそのまま（さかのぼって変えない）。探求ボードでは「重点の外の実験中」として薄く分けて出す
- 重点の問いを候補・解消などに戻しても、つながる実験中はそのまま（上の「重点の外」に出る）
- REFLECT-UPDATE の上限の判定・理由文も同じ規則に（「重点の問い『…』の実験中が5本のため…」）
- `docs/prompts/reflect-sparring-prompt.md` の「重点3件・実験中5件」を「重点3件・実験中は重点の問い1本につき5件」に

## 3. 問い・実験に「保管」

- 新しい状態 `stored`（表示名「保管」）を問い・実験の両方に
- テーマ・問いにつながっていなくてよい。候補の一覧・本数・上限・`reflect_focus_v1`・Task OS の要約に入れない
- 探求ボードの末尾に折りたたみ「保管」（外したテーマと同じ形・件数バッジなし）。開くと全件、各行に「候補に戻す」
- 画面：問い・実験の操作に「保管」を足す（候補・重点・実験中から保管へ）
- REFLECT-UPDATE：`ステータス：保管`（問い・実験）。保管から `ステータス：候補` で戻せる。保管から重点・実験中へ直接はできない（いったん候補）
- 四半期の棚卸しで並べるのは担当がバックアップから読む（`status:'stored'`）

## 4. 使わない欄を外す

調べた結果（11/3・コードとバックアップ 10/31 夜）：

| 欄 | 書く・読むOS | 中身があるもの | 外す支障 |
|---|---|---|---|
| e. テーマの関連PJ `relatedPj` | Reflect OS だけ（5か所） | 抽象の3本（仲間づくり→PJ2本、挑戦の環境づくり→1本、自分らしい生き方とは何か→2本） | なし（PJとのつながりは問い・実験の `links.projectId` で持つ） |
| f. テーマのマイルストーン `milestones`・指標 `metrics` | Reflect OS だけ（100LIST の `milestones` は別物） | 完了のテーマ5本（2億円PJ・仲間の定義・意思決定の数字・3AC 2030 VISION・社内新規事業）にマイルストーン13件・指標6件 | なし |
| g. 実験の実践回数 `practiceCount`・最後の実践日 `lastPracticedAt` | Reflect OS だけ（表示1か所・古い名前からの移し替え1か所）。Task OS・Lectica・Morning Brief は読んでも書いてもいない | 実験3本 | なし（実践の事実は Lectica のログが正） |

**外し方（起動時1回の移行で上の §1 と一緒に・同じ退避キー）**
- 入力欄・表示を外す
- 中身は**消さずに記録へ移す**（削除ではなくアーカイブの原則）：
  - `relatedPj`：テーマの `notes[]` に「（旧「関連PJ」欄）{PJ名}・{PJ名}」1行（PJ名は Project OS から id で引く。引けなければ id）
  - `milestones`／`metrics`：テーマの `notes[]` に、1件1行で「（旧マイルストーン）{名前}｜{状態}｜{期日}」「（旧指標）{名前}｜{目標}｜{実績}」（あるものだけ）
  - `practiceCount`／`lastPracticedAt`：実験の `notes[]` に「（旧「実践回数」欄）n回・最終 YYYY-MM-DD」1行
- 移したあと、その欄をデータから消す（退避キーに元が残る）
- 移行の件数を console に。トーストは「探求ボードの使わない欄を記録へ移しました」1回

## 5. 変えないこと

- 重点の問いの上限（3）、下書き、統合の引き継ぎ（実験中の引き継ぎは §2 の規則に従う：重点につながらない実験は実験中で引き継がない）
- `reflect_focus_v1` の形（`unlinkedExperiments` は残す。中身は「重点の外の実験中」）

## 6. 受入条件（playwright・10/31 以降のバックアップ相当）

1. テーマに「問い」欄が無く、カードに重点の問い（無ければ「重点なし」）。元の文は記録に1行ずつ。Task OS 要約の `themes[].question` は重点の問いの題名
2. `■ テーマ` の `問い：` はそのブロックだけ読めない
3. 重点の問いAに実験中5本 → 6本目は不可。重点Bには別に5本まで。重点でない問いの実験・つながっていない実験は実験中にできない（画面・REFLECT-UPDATE・統合）。既存の重点外の実験中はそのまま・薄く分けて表示
4. 問い・実験を保管 → 一覧・数・上限・`reflect_focus_v1`・要約から消え、「保管」の折りたたみに出る。「候補に戻す」と `ステータス：候補` で戻る。`ステータス：保管` で入る
5. 関連PJ・マイルストーン・指標・実践回数の欄が画面に無く、中身は記録に移り、データから消えている。退避キー1つ、再読み込みで二度走らない
6. 「直前の更新を元に戻す」で戻る。375px・コンソールエラー0・構文検証OK・両OSの SW 版上げ（task-os は BUILD_VER も）
