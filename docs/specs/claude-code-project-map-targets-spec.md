- **ターゲット**＝プロジェクトの中の単位（旧「戦略目標 S01〜S05」はこれになった）。**案件**＝ターゲットの中で動いているもの。

## §2 データの器（`project-os/index.html`）
`pos_v4` の `projects[]` に次を足す。新しい localStorage キーは作らない（バックアップは `pos_v4` 丸ごとなので Task OS 側の変更が要らない）。

```js
p.kind     // '通常' | '維持活動'   無ければ '通常' として扱う
p.mapOrder // 1,2,3…  全体の地図での並び（A,B,C…の順）。無ければ地図の最後に並ぶ
p.targets // [{ id, title, status, order, items:[{ id, title, due, src }] }]
```
- `targets[].status`：`'進行中'`｜`'保留'`｜`'完了'`。無ければ `'進行中'`。
- `items[]`（案件）：`title` は必須。`due`（YYYY-MM-DD・任意）。`src`（任意・表示しない）＝`{kind:'fork'|'constraint'|'phase'|'attention'|'centerPin'|'nextMove'|'goal'|'text', pid, date, title}`。§5 で自動投入するとき、どの PJ のどの記録から作ったかを残す（**元の記録が別の PJ にあることがある**ので `pid` を必ず入れる。`date`・`title` は元の記録の日付と題名。id ではなく日付＋題名で辿れればよい）。
- id は既存の `uid()` と同じ作り。
- **既存の欄（phases・forks・constraints・attentionIssue・moves）は消さない・動かさない。** ターゲットと案件は「見方の器」で、分岐や制約の正本はそのまま。

## §3 全体の地図（ホームの一番上）

### 3-2 形（PC・左から右の3列。デザインシート「Project OS 全体の地図 イメージ」ver2.2 と同じ）
- 列1 **プロジェクト**：`status!=='完了'` の PJ を **`mapOrder` の順**（無いものはその後ろに、配列の順）。カードに **名前と `goal`（ゴール）だけ**。`status==='保留'` は点線の枠で薄く、`kind==='維持活動'` は名前の後ろに「（維持活動）」。
- 列2 **ターゲット**：`targets` を `order` 順。`status==='保留'` は点線で薄く。
- 列3 **案件**：各ターゲットの `items`。`due` があれば末尾に `M/D`（年が違えば `YYYY/M/D`）。
- プロジェクトごとに薄い帯（`#f3f1ec` 程度）で囲む（ゲシュタルトの法則）。親→子は縦の幹＋横の枝で線を引く（依頼書1と同じ描き方）。カードの高さは中身で変わるので、線は実寸から引く。
- **番号**：描くときに振る（保存しない・公式の番号ではない。並びが変われば振り直される。本人が地図を見て「8 は ③ へ」のように指示しやすくするためのもの）。
  - プロジェクト：地図の並びで A・B・C…
  - ターゲット：**地図全体の通し番号** ①②③…（プロジェクトが変わっても続ける。A の最後が ④ なら B の最初は ⑤）
  - 案件：**地図全体の通し番号** 1・2・3…（同じく続ける）
  - デザインシート「Project OS 全体の地図 イメージ」ver2.2 と同じ振り方。
- 目立たせるのは2つだけ（黄土色 `#8a5300`／`#fbf0dc`）：ターゲットが無いプロジェクト→「ターゲットなし」、案件が無いターゲット→「案件なし」。赤は使わない。
- 件数バッジ・催促・「0件」表示は出さない。

### 3-3 詳細パネル（プロジェクトのカードを押したとき）

- 右上に「×」（44px）。パネルの外を押しても閉じる。
- パネルから「詳細を開く」で `nav('detail', pid)` 相当に飛べる（今の PJ カードと同じ遷移）。パネル自体は読むだけ（編集しない）。
- ターゲット・案件のカードを押したときは何もしない（将来の編集は 3-4）。

### 3-4 ターゲットと案件の編集（画面）
- 詳細画面（`renderDetail` 2365〜）の本文の並び（`quickAddHtml` → `movesHtml` → `collapsesHtml`）で、**`collapsesHtml` の中の先頭**（「詳細メタ」の折りたたみより上）に **「ターゲットと案件」** の折りたたみを足す（既定は閉じる）。
  - ターゲット：追加（題名）・題名の編集・状態（進行中／保留／完了）・並び替え（上へ／下へ）・削除（確認あり）。
  - 案件：ターゲットの下に追加（題名・期日）・編集・削除。別のターゲットへ移す（選択）。
  - 削除は「退避してから」（`pos_backup_lastedit` のような1世代の退避キーに `pos_v4` の文字列を残し、取り込み画面の「直前の取り込みを元に戻す」と同じ形で戻せる）。実データは消さない方針（記録の地図 前提）。

### 3-5 PROJECT-IMPORT（受信箱）での直し
`piParseText`（1745〜）の受け付けるラベルに次を足す。書式は「分岐:」「制約:」と同じ流儀。
```
PJ: スリーエーグループ2030構想
種別: 通常                          ← 通常／維持活動
ターゲット: 事業計画作成（進行中）／IPO準備。削除：旧ターゲット名
案件: 事業計画作成 ＞ スリーエーグループ2027年事業計画策定 2026-12-15／IPO準備 ＞ ハイクラス人材活用（乾さん入社）。削除：事業計画作成 ＞ 古い案件名
```
- 1件の PROJECT-IMPORT は今までどおり **1つの PJ** に効く（`PJ:` 行の PJ）。ほかの PJ のターゲットは書けない。
- `ターゲット:`：「／」区切りで1件ずつ。**同じ題名があれば状態だけ直し、無ければ足す**（置き換えではなく追記）。末尾の全角カッコの中が **進行中・保留・完了 のどれかのときだけ**状態として読む（「関連当事者取引解消（借金返済）」のように題名の一部のカッコは題名のまま）。`削除：` は題名一致で消す（退避あり）。
- `案件:`：「{ターゲット題名} ＞ {案件題名} {YYYY-MM-DD 任意}」。題名に「／」は使えない（区切りと重なるため。§5 の投入題名も「・」で書いてある）。ターゲットが無ければ**そのブロックだけ保留**にして summary に「ターゲットが見つかりません：…」（勝手に作らない）。同じ題名の案件があれば期日だけ直す。
- 読めない値は今までどおり summary の「読めませんでした：…」「読まなかった項目：…」に出す。適用前の退避（`pos_backup_lastimport`）と「直前の取り込みを元に戻す」は今のまま効かせる。
